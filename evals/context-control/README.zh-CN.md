# 上下文与控制配对探针

[English](README.md) | [简体中文](README.zh-CN.md) · [文档目录](../../docs/README.zh-CN.md)

从仓库根目录运行：

```sh
node --import tsx evals/context-control/run.ts --live --runs=3
```

使用已配置模型并计费。输入为合成案例，不含项目文件、私有聊天和密钥。六类案例覆盖双语约束、修订要求、重复、事件等待、有效进展及验证。保留实验共享两次摘要后的历史，开启组追加原始来源；控制实验共享事实，开启组追加策略建议。轮次间交换组顺序。

版本化报告包含配置、样本、正确性、用量、按价估算成本和耗时，摘要共享成本另列。这是消融烟雾测试，不是端到端编码基准；持平只说明没有观察到收益。缓存冷热、小样本、固定模板都限制比较。

## 上下文准备回归检查

完整团队协议现在在发现团队工具、已有团队或明确选择 host/creative 模式时加载。初始提示保留简短能力入口和既有权限规则；激活前将 4,458 字符替换为 501 字符，减少 3,957 字符（不是实测 token 节省）。关闭记忆时省略其管理说明。已有 `context.cache_observed` 事件记录请求组成大小；`context.guidance_loaded` 记录协议加载，不在事件中复制提示词正文。

压缩后，在保留历史之后各保留一份最新运行配置、任务快照和工作流协议。被替代的快照不再进入摘要；原始用户要求、完整工具调用组和信任／来源账本仍受保护。正常步骤在压缩前保持追加方式，以保留可复用前缀。

`tests/context-guidance.test.ts`、上下文复用与运行时测试无需真实模型即可检查发现机制、权限、快照顺序及证据保留。这些检查证明输入缩减与状态一致性，不证明意图理解能力提升。后者应使用相同模型多次运行配对工程任务，覆盖模糊目标、新证据推翻诊断、目标服务不可用等情形；比较实际请求参数、工具结果及首次分歧决策，不能把同模型表现差异归因于未经测量的机制。

运行时还提供带观测时间的初始时间快照与只读 `read_clock` 工具，返回 UTC、指定 IANA 时区（默认明确标为主机时区）、本次运行创建后的经过时长，以及最新记录状态持续时长。经过时长包括等待和停机，不是有效工作或 CPU 时间。时间戳缺失或时钟倒退时，无法确定的时长返回未知。应在决策节点查询，未来唤醒使用已有调度工具。`tests/runtime-clock.test.ts` 覆盖时区换算、作用域、权限和时钟异常。
