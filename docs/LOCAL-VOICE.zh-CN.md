# 本地语音与回复朗读

[English](LOCAL-VOICE.md) | [简体中文](LOCAL-VOICE.zh-CN.md)

## 架构与隐私

可选服务监听 `127.0.0.1:8812`，通过令牌鉴权，提供 OpenAI 兼容转写和语音合成接口，复用现有媒体任务、播放、下载和工作区导出。推理时音频与正文留在本机；准备阶段下载公开代码和模型。不自动回退云端，公共设置不暴露密钥。

SenseVoice 用于短录音多语言转写，faster-whisper 提供片段时间戳，CosyVoice 3 使用本地参考 WAV 和准确文字合成语音。它们不是实时语音对话模型；当前返回完整 WAV，不是流式语音，不承诺说话人分离或自动配音对齐。

## 安装和启动

准备 Python 3.10/3.11、Git，以及 PATH 中可访问的 FFmpeg。Windows 可运行 `Setup-Local-Voice.cmd`（Python 需在 PATH）。跨平台入口，也适用于 PowerShell AllSigned 阻止未签名脚本的环境：

```text
python scripts/local_voice/manage.py setup
python scripts/local_voice/manage.py start
```

使用三个独立环境：`.data/voice-asr-python`（SenseVoice）、`.data/voice-whisper-python`（Whisper，不安装 PyTorch）、`.data/voice-tts-python`（CosyVoice）。隔离 CTranslate2 与 PyTorch，避免 Windows OpenMP 冲突；固定兼容的原生依赖，包括 SentencePiece 0.2.0、CTranslate2 4.4.0。旧版双环境安装需要重跑 setup 迁移。不修改 RAG、ComfyUI、评测环境。`--asr-only` 仅准备转写；`--skip-download` 仅装依赖，不下载模型。中断后重新运行可续传。记录实际模型 revision 和 CosyVoice 源码 revision。上游原生依赖可能需要编译工具或平台配置，安装失败不等于服务就绪。

配置与权重在 `.data/voice-service`（或 `AGENTDEMO_DATA_DIR` 下）。离线用户可把完整模型快照放到 `config.json` 的 `models` 路径。推理使用本地路径与 Hugging Face 离线模式，不自动下载缺失权重。推理进程通过 Python 审计钩子阻止网络连接，包括上游可选文本规范化器的隐式下载；这不是任意原生代码的安全沙箱。

没有已配置音色且上游示例录音存在时，安装使用该示例作为默认音色。设置 → 媒体与语音 → **本地音色**支持上传不超过 30 秒的非空录音（建议至少 3 秒）（最多 25 MiB），填写名称和准确原文，保存后中英日试听、设为默认朗读音色。上传文件在本机统一为 24 kHz 单声道 WAV，以随机 ID 保存，不使用上传文件名作为路径。保存后下次请求即时生效，无需重启；选择默认音色只更新本地语音连接，表单中其他未保存修改保留。试听会运行本地推理，CPU 可能耗时一两分钟。这是参考音色条件合成，不是训练新模型。

高级用户也可在 `config.json` 配置音色：

```json
{
  "voices": {
    "default": { "audio": "D:/Voices/reference.wav", "text": "这段参考录音的准确文字。" }
  }
}
```

使用有权使用的录音。客户端不能通过合成接口传入任意磁盘路径。启动后，在设置 → 媒体与语音中选择“添加本地语音连接”（先保存其他修改），添加 SenseVoice、Whisper、CosyVoice，不重复添加、不覆盖原有录音服务选择。可另外选择默认转写服务。添加连接不等于依赖、权重和音色已通过实际推理验证。

配置后 `Start-Amadeus` 一并启动轻量服务；首次启动支持 `-LocalVoice -Python <解释器路径>`。普通启动不安装依赖、不加载语音模型。后台进程独立于 Codex，关闭 Codex 不会随之退出；不会自动重启已有服务。

## 资源管理

新安装默认 `device: "auto"`，保留已有设备选择，默认两个 CPU 线程。`device: "cpu"` 不分配显存。ASR 仍使用一次性进程；TTS 按需加载单个模型，连续请求复用。默认空闲 60 秒释放，`warmIdleSeconds` 可设为 0–300 秒；每两秒检查一次空闲期限和剩余显存。`warmReserveMiB` 默认 1024，是已加载模型的执行余量，不是冷加载阈值。切换模型、设备或运行环境，以及失败、超时、流式断连时释放工作进程。首次启动不加载模型。

`device: "auto"` 每次请求前读取指定 NVIDIA 显卡的剩余显存，不探测任何应用或队列。显存不足或无法读取时回退 CPU。若随后出现 GPU 不可用或显存不足错误，在 GPU 工作进程退出且尚未发送流式音频时，仅尝试一次 CPU；其他错误不自动重放。`device: "cuda"` 不满足条件时报错，不自动回退。`gpuIndex` 选择显卡，`minFreeMiB` 默认 8192，是保守准入阈值而非模型实测最低需求。状态显示剩余及要求的 MiB 数。检查后其他程序仍可能分配显存，因此不是独占预留；CPU 模式完全不分配 GPU 显存。旧配置的 `comfyUrls` 被忽略，新配置不再生成该字段。

安装匹配的 NVIDIA 依赖可使用 `python scripts/local_voice/manage.py setup --cuda` 或 `Setup-Local-Voice.ps1 -Cuda`，此前应停止语音服务。CUDA 12.1 的 Torch 2.3.1 包同时提供 Windows CTranslate2 4.4 所需的 CUDA/cuDNN 库。普通启动不下载这些大包。CPU/GPU 主要差别是速度，但精度、量化和合成采样也可能导致输出不同，不能承诺完全一致。

同时仅运行一个语音请求，其余返回 `VOICE_BUSY`，不自动重放。上传最多 25 MiB，录音最多十分钟，合成正文最多 4000 字符，模型进程最多 150 秒（小于现有媒体 HTTP 超时）。超时清理包括本次工作进程的子进程树，涵盖 Windows 虚拟环境解释器转发进程。CPU 冷加载可能超时，此时缩短录音或分段合成。超长音频报错，不悄悄截断。FFmpeg 统一浏览器录音/WebM/MP3 格式。依赖缺失、权重缺失、超时和 GPU 准入错误提供不同诊断。

## 朗读助手回复

每条助手消息下方复制、分支、点赞和点踩后增加朗读按钮。选择语音服务并点击开始，只发送该条回复的正文；跳过代码块、图片地址及尚未发送的草稿。长回复逐段生成和播放。本地连接设置 `read_aloud_units: 20`，非 ASCII 字符计 1 单位，ASCII 计 1/4，优先在句子边界断开，降低 CPU 长段超时风险，但不保证发音时长。其他服务保留常规分段，此界面提示不会发给语音服务商。同时仅一条消息朗读。停止或切换对话会停止播放并禁止后续提交；已经提交的生成可能继续，产物保留在媒体历史，停止播放不等于服务商取消或退款。开始按钮旁提示远程服务可能收费。浏览器禁止自动播放时可在播放器手动点击。新回复不会自动朗读。

## 本机实测（2026-10-19）

Windows 上六项鉴权 HTTP 请求通过，均实际验证了 CUDA 不可用后自动回退 CPU：

| 请求                  | 总耗时          | 结果                                    |
| --------------------- | --------------- | --------------------------------------- |
| SenseVoice 中文／英文 | 13.62／13.56 秒 | 正确转写短句                            |
| Whisper 中文／英文    | 19.58／15.83 秒 | 正确文本及片段时间戳                    |
| CosyVoice 中文／英文  | 59.34／86.03 秒 | 24 kHz 单声道 WAV，音频长 2.64／5.24 秒 |

直接合成后再次转写也恢复了中英文测试句子。这是短样本冒烟测试，不代表总体准确率或人工听感认证。GPU 准入与显存不足回退有确定性测试；**独立复制已有运行库后，GPU 六项真实 HTTP 测试也全部通过**，没有向来源环境安装依赖。没有修改 benchmark 或 ComfyUI 环境。每次冷加载、两个 CPU 线程下，CPU 合成明显慢于实时。

GPU HTTP 总耗时：SenseVoice 中文／英文 **11.17／11.44 秒**，Whisper **6.88／4.41 秒**，CosyVoice **32.83／25.28 秒**（输出音频 2.84／4.52 秒）。短样本包含冷启动，不能推广成所有任务的提速比例。SenseVoice/CosyVoice 复用了独立复制的 **PyTorch 2.6.0+cu118、CPython 3.11** 包；Whisper 使用独立复制的 CUDA 12/cuDNN 8 DLL。ComfyUI 的 PyTorch 2.11.0+cu128 仅检查，未修改或采用。已停止不再需要的 CUDA 下载。

可选高级字段 `torchRuntimePath` 指向独立复制的兼容包目录，仅 GPU Torch 工作进程使用，CPU 仍用原环境；`cudaLibraryDirectory` 指向 Windows CTranslate2 所需的 CUDA 12/cuDNN 8 DLL。这两项不修改全局 PATH 或来源环境。复用前应核对 Python ABI、依赖和 CUDA/cuDNN 版本，并实际推理验证，不能直接认为新版本必然兼容。默认配置没有硬编码用户名或本机来源目录。

## 参考音频限制与语言

音色接口将本地 CosyVoice 适配器的限制提供给界面。本机上游 `cosyvoice/cli/frontend.py::_extract_speech_token` 明确拒绝 **超过 30 秒**的参考音频，普通零样本与跨语种路径均受此限制。**至少 3 秒**是质量建议，较短录音只提示、不因此拒绝，**25 MiB** 是上传保护，不是模型限制。长录音应先选取片段并填写对应原文，不会静默截断；这不是输出朗读长度上限。未来其他适配器需要声明自己的限制。

参考语言可选，包括日语，只记录用途，不强制输出语言，也不翻译原文。支持中文、英文、日语试听，保存前可以播放上传录音。静音录音拒绝导入，低音量与削波会保存并显示提示。这些信号检查不能验证说话人身份、转写准确性或听感。使用已授权素材，并实际试听跨语言效果后再采用。无新增依赖，无需修改启动或首次启动脚本。

## 朗读展示

消息底部一键开始朗读，暂停／继续、停止、速度与服务选择集中在紧凑控件内。分段预算允许有界延伸到句末，当前段播放时最多提前生成下一段。旧版或远程服务使用有限预加载，并非原生流式。新版本地 CosyVoice 另支持模型原生流式：同一个工作进程边推理边输出 WAV 块，经鉴权代理转发，Web Audio 使用同一播放时钟连续调度，不生成媒体卡片。成功请求后的模型按上述空闲期限短暂复用；失败或断连不保留。客户端提前调度约 30 秒音频（外加一个有界音频块），无音频进展 150 秒或总时长 10 分钟即中止；断开连接只终止自己拥有的工作进程。GPU 故障只允许在尚未输出任何音频时回退 CPU，部分播放后不自动重播。需要新版本地监听服务；只有开始合成前明确拒绝流式能力时才回退旧路径，中途错误不会自动重新提交。停止会取消客户端轮询并防止后续提交，已经提交给服务的生成可能继续。朗读回执仍保存并可通过媒体 API 查询，但不再刷屏展示在对话媒体卡片中，旧回执按原始操作标识兼容处理。用户主动生成的语音仍正常展示。

本次验证：全量 Node 回归通过（591 项：582 通过、9 跳过），随后新增代理测试也通过；Python 语音回归 16 项以及类型、构建、文档检查通过；浏览器真实参考录音导入与 FFmpeg 解码通过。日语试听未在浏览器测试期限内完成，不能宣称此次已验证日语听感。

流式实际短句测试（2026-10-19，上游示例参考音色，非质量基准）：CPU 中文首块 53.77 秒／完成 84.84 秒，英文首块 64.09 秒／完成 90.64 秒；GPU（CUDA）中文首块 25.66 秒／完成 26.97 秒，英文首块 20.25 秒／完成 21.75 秒，均输出两块且正常结束。包含冷加载，仍不能等同在线服务的即时响应。浏览器另验证了 WAV 解码、暂停／继续／停止、旧朗读卡隐藏与主动生成语音保留。

GPU 选择现在仅依据可用显存，与 ComfyUI 或其他具体应用无关。更新需要重启 Agent 和本地语音监听服务，无新增依赖、模型下载或首次启动步骤。原生流式只用于实时朗读，不额外保存为聊天媒体产物；常规语音生成仍保留原有文件交付路径。

朗读按声明的 `wav-ndjson-v1` 能力选择服务，不依赖内置连接 ID 或固定端口。在媒体设置中仅为实现该 NDJSON WAV 分块契约的服务开启；地址/模型更换后重新确认。本地 `voice-service/config.json` 可选 `listenPort`（默认 8812），启动、健康检查、连接注册与试听共用该值。改端口后重启监听服务，并重新添加本地连接以刷新地址。已有默认安装无需手动迁移，无依赖及首次启动步骤变化。

## 预置与参考音色统一发现

保留参考音色克隆。可选的官方 [CosyVoice-300M-SFT](https://huggingface.co/FunAudioLLM/CosyVoice-300M-SFT) 使用预训练说话人，无需用户参考录音，独立于现有 CosyVoice 3 模型。首次安装不强制下载；需要时使用已配置的 TTS Python 执行：

```text
python scripts/local_voice/prepare.py --config .data/voice-service/config.json --models cosyvoice-sft
```

模型下载完整后才发布路径与音色目录；保留用户现有音色和默认选择，失败可重跑复用下载缓存。上游快照约 2.6 GB，按 revision 固定。音色名称读取 `spk2info.pt`，不按营销页猜测。设置中的本地音色列表同时显示参考音色与预置音色；预置条目使用 `preset:` ID，通过同一语音连接选择，推理时按实际模型加载，空闲期限到达后释放显存。已有安装更新监听服务后支持该路由；不需要替换现有克隆模型或重新创建克隆音色。

`media_services` 向 Agent 返回匹配本机连接的音色 ID、名称、来源与语言元数据。它不返回参考录音、转写原文或私有路径。Agent 用 `generate_media` 的 `options.voice` 指定实际 ID；用户指定优先，重复角色保持一致。这适用于旁白、角色对话和其他语音任务，不绑定跑团场景。未知提供商不会被冒充有完整音色目录；保留其已配置的 voice 默认值。生成语音仍适用既有权限和费用规则，不代表允许自动播放历史消息。

## 播放缓冲与开发验证

原生流式起播预留 1.5 秒调度缓冲；如果后续音频晚于播放游标，重新积累 0.5–3 秒缓冲。已有片段保持同一音频时钟连续衔接，重复、缺序号、错误结束会停止本次队列，不悄悄跳过。持续生成慢于播放仍可能等待；这不是模型加速，也不会凭空补出模型漏读的文字。

诊断只用于开发测试，日常设置不增加诊断下载选项，也不要求用户分析日志。测试可显式传入有界、内存中的 `ReadAloudDiagnostics`，记录发送正文、服务端正文哈希、原始 WAV 块、到达/解码/调度/结束回调时间。计划播放时间并非扬声器实测；浏览器结束回调也可能延迟。默认不保存正文或声音诊断。

2026-10-19 普通上游示例音色 CUDA 实测：首块约 17.44 秒，9 块合计 29.68 秒音频，总生成约 39.31 秒。1.36 秒音频之后等待 1.47 秒，下一块 2 秒音频之后等待 2.94 秒，足以让原先的低缓冲播放断粮；按该时序回放，1.5 秒初始缓冲未出现调度空隙。所有块拼接后的 PCM 与完整生成音频逐字节一致。中文普通测试的对白和长短句由两种 ASR 交叉核对，未发现段落遗漏或日文；其中 Whisper 在音频实际末尾之后产生了额外转写，不能将这种转写错误当作 TTS 串音证据。此结果不是所有音色或跨语言质量保证，未验证角色音色。

浏览器回归：设置 `AMADEUS_TEST_SPEECH_BROWSER=1` 后执行 `node --import tsx --test tests/read-aloud-browser.test.ts`，使用安装的 Edge 和普通合成测试波形验证真实 AudioContext，默认 CI 不要求下载浏览器。常规自动测试覆盖正文透传、字节保真、重复/取消、缓冲、目录隔离和内存上限。历史漏读与语言偏移若未在普通样本复现，不标记为已彻底解决。

追加预置模型实测：中文女、英文女、日语男均在 CUDA 上生成文件，耗时约 23.9/34.8/21.3 秒。中英文测试句通过独立 ASR 内容核对；**日语男未通过**，SenseVoice 与 Whisper 都转写出明显偏离输入的内容。相同文本的非流式与语言标记对照也未通过；没有把这些对照参数写入生产路径。下载成功、返回 WAV、CI 通过均不能替代语言质量验收。其余四种预置音色尚未逐一做内容质检，选择前仍需试听；本次保留全部可选项和已有克隆能力，不宣称所有音色都已验证。

## 2026-10-19 连续朗读与耗时核对

GPU 普通上游示例音色，同一段中文冷/暖两次：总耗时 24.23/8.95 秒，首块 16.86/3.56 秒；冷启动依赖导入 7.36 秒、模型加载 7.25 秒。暖请求确认复用模型。两次 SenseVoice 独立 CPU 转写均覆盖正文、引号内对话和最后一句，没有额外日文；这是有限样本，不是所有音色的质量保证。独立测试将空闲期设为 4 秒，确认 worker 退出释放。生产默认仍是 60 秒。

worker 回执提供 importsSeconds、modelLoadSeconds、modelReused，以及各块 generationSeconds、cpuCopySeconds、writeSeconds、readySeconds、audioSeconds。generationSeconds 包含上游文本处理、参考特征提取和生成器等待，不等于纯 GPU kernel 时间；CPU 搬运可能包含 GPU 同步。高精度计时不主动加入全局 CUDA 同步，避免改变流水线行为。健康接口仅返回耗时，不返回正文或参考录音。开发测试可在私有目录关联发送文本、回执、WAV 与浏览器诊断；普通用户不需要下载诊断文件。

首次测试使用 Windows 单调时钟，亚毫秒阶段显示 0 不等于零成本；代码已改为高分辨率性能计时。播放缓冲继续吸收块到达抖动，缓存只改善加载成本，不保证持续生成速率。

克隆保留；CosyVoice3 的参考提示前缀只用于第三代模型，不注入其他代际。未改写正文、未删去日语、未剪掉疑似错误音频来掩盖问题。此前 Japanese SFT 内容检查失败仍未解决；历史克隆漏读及额外日文尚未用普通样本稳定复现，不能宣称修复。部署前须独立判断功能测试通过与内容质量通过，不能将 CI 当语音质量认证。

### 自建音色删除

设置的音色选择旁仅对用户上传的 UUID 克隆显示“删除自建音色”，操作前确认。内置默认和预置音色不提供删除。正在作为默认使用的克隆须先改选其他音色。删除立即撤销目录选择并移除名称及原文；保留无正文的删除标记，语音服务在当前请求结束后或收到空闲清理请求时，仅删除自己 voices 目录内对应的 UUID 录音。服务离线时明确显示等待清理，下次语音请求再清理；不会删除外部源文件、已生成音频或模型权重。已提交的合成可完成，之后引用旧音色的任务明确失败，不暗中换音色。

长文实测：用户提供的镜子故事使用普通上游音色，输出 22 块、80.64 秒，生成约 88.67 秒（含冷启动和清理）。分块 PCM 与完整 WAV 逐字节一致。独立 SenseVoice 转写覆盖此前漏读的段落，没有检出额外日语，但存在个别字词差异；这不是逐字发音正确的保证。按这组实际到达时序计算播放缓冲，无调度空档；尚不等于真实扬声器全链路无卡顿，也不代表历史克隆案例已修复。

参考特征复用：使用上游 `add_zero_shot_spk` / `zero_shot_spk_id` 接口，在内存保留最多一个参考特征项。按录音内容 SHA-256 与准确原文判定失效，不只看文件名或修改时间，不写回模型权重。更换参考时移除旧项；空闲/压力释放、删除录音清理或服务结束时退出进程清除特征。新增 `referencePrepareSeconds`、`referenceReused` 指标。

同一长文的单次前后对照：参考缓存后总耗时 61.22 秒，之前 88.67 秒，完整 WAV 的 SHA-256 一致（`21f20016fe38ce2f47e19d329e3e683ae339fd19db0e0a4182cf69fff2e6c7b3`）。这是本机一次对照结果，实际加速幅度受负载影响，不能保证每次如此；参考提取不再随每个文本片段重复。
