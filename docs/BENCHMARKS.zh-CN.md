# Amadeus 评测方案

[English](BENCHMARKS.md) | [简体中文](BENCHMARKS.zh-CN.md)

## 目标和当前完成状态

评估 **模型 × Runtime × 任务 × 环境** 的组合，不以测试数量或主观架构分数代替实际成功率。文章提供的多维评估思路可取，但示例代码、榜单和版本必须回到官方实现核对：[参考文章](https://blog.csdn.net/u013010473/article/details/157695931)。

适配器现已覆盖 BFCL 11 个 Python／实时单轮类别、LongMemEval S／oracle 完整上下文问答、GAIA 验证集。环境准备、实际执行与评分是独立阶段；LongMemEval 这条协议不代表持久记忆系统评测。

## 分阶段执行

1. **阶段 0：无模型费用检查。** 容器和评分器正反例、超时、只读挂载、环境 reset；无成绩宣称。
2. **阶段 1：10 道 SWE 任务。** 按仓库分层、固定随机种子，名单先冻结，再生成；先确认 gold 能通过、空补丁不能错误通过。排除项保留原因，不按生成结果挑题。
3. **阶段 2：100 道配对任务 × 3 次重复 × 2 个配置 = 600 次尝试。** 按仓库和可得难度分层。相同任务独立重置，AB/BA 交错次序；抽样成绩不得写成完整 Verified 成绩。
4. **阶段 3：完整公共测试集与其他赛道。** 每个赛道独立给结果。终端先 10 道、网页先 10 道、记忆先 20 道验证适配器，再扩展。不能汇总为一个“全面超过”分数。

基准对照：

- A：生产单 Agent，同模型和权限。
- B：仅关闭 read-result reuse；当前已有的编码试点实现。**不等于全部上下文优化关闭**。
- C：Team，在公共适配器完成后加入；每次尝试主/子 Agent、审核、重排、模拟器共享总 token、费用和时间预算。
- D：以后需要完整 context-off 时逐项实现并证明消融发生；未实现则标 unavailable，不能只改标签。

默认先并发 1；环境稳定后 2。建议初始每任务 2 CPU / 4 GiB / 20 分钟，评分超时另计且独立限制；这是起点，先按官方任务要求校验，资源不足标 infrastructure error。不改变日常 Agent 全局设置。真实 API 批次启动前必须填写模型、价格来源、每次/批次费用预算；价格未知则不能声称硬预算已满足。600 次不是本次已经执行的任务数。

## 适配器契约与隔离

生命周期：prepare → reset → solve → collect patch/artifact → stop agent → grade → archive → cleanup。

每个 attempt 独立数据库、任务容器、工作目录、会话、Memory 与检索缓存。只把题目、基础代码和允许资源给 Agent；gold、隐藏测试、答案和评分器目录不得挂入解题容器。官方镜像用于解题前必须检查是否已带隐藏测试，必要时分离 runner/grader。

主机运行模型连接，容器运行代码工具；候选代码拿不到密钥、Docker socket 或评分器。官方 harness 是可信宿主编排器，它可管理 Docker；**不能把这份权限交给候选代码**。Docker 后端每次临时启动一条命令，不自动等价于公共基准要求的持续任务环境；适配器需把所有文件/命令操作路由到同一 attempt。

限制 cap、进程数、CPU、内存、总时限、文件/输出量。安装依赖放在准备阶段；解题阶段默认断网。WebArena 使用仅通往测试站点的内部网络。需互联网的任务另分组，记录允许域名。失败不回退宿主执行。

一次 attempt 中断且结果不明，不静默续跑或重复副作用；保留 interrupted_unknown，另开 attempt。评分器可对同一冻结产物重新评分，但必须记录评分器版本与新评分 ID。

## 记录与统计

每次保存：run/attempt/task ID、Git commit 与 dirty patch 哈希、数据 revision、任务列表和输入哈希、grader commit、镜像 digest、模型/endpoint（去密钥）、参数、工具/权限、预算、随机种子、环境资源、起止时刻、产物哈希与原始官方 report。

指标：

- 成功率 pass@1、完整/部分/超时/基础设施错误/未开始；所有预定任务保留在分母，另列可评分子集。
- 三次均成功的可靠性单列；pass^k 和 best-of-k/pass@k 不混用。
- 输入、其中缓存输入、输出、全树总量；缓存输入已包含于输入，不能重复相加。
- 实际 API 账单优先；估算费与实际费分开，未知用 null，绝不写 0。
- 端到端与纯执行延迟 p50/p95、工具调用、重试、压缩、停滞、恢复、人工介入与队列等待。
- 错误完成声明、越权副作用、跨范围泄露、残留进程、资源峰值。
- 配对成功率差与任务级 bootstrap 95% CI，重复尝试不能当成独立任务；单组成功率可报 Wilson CI。同时报告绝对数。
- 费用/成功任务包含失败尝试消耗；无成功则为未定义。API 内部重试不可观测就用 null。
- 冷/暖缓存单独设计和记录；同一配置先跑可能影响 provider 缓存，不能强称随机次序等于冷缓存。

RAG：Recall@10、nDCG@10、引用支持率、不可答查询误答率、跨语言分组、索引覆盖率、延迟。阈值只在开发集调，留出测试集固定。Memory 评估真实形成与召回，不向索引器泄露未来问题；纠错、过期、项目隔离和冲突单独测。Team 用相同全树预算；同源证据不算多份独立支持。

## 维度覆盖矩阵（补充核对）

文章第 4 节分为任务完成度、过程质量、效率与成本、安全与可靠性。以下是本项目具体化的测量方案，不照抄文章示例评分代码。

| 维度     | 测什么                                         | 在本套件如何测                                                                     |
| -------- | ---------------------------------------------- | ---------------------------------------------------------------------------------- |
| 结果     | 完成、准确、部分目标达成、产物质量             | 官方 verifier + 明确的目标条件；部分分数单列，不覆盖官方通过率                     |
| 过程     | 有效动作、规划执行一致、工具选择、错误恢复     | 可观察 action/state 轨迹；错误参数率、无进展重复率、失败后恢复率；不要求隐藏思维链 |
| 效率     | 步数、延迟、token、费用、资源                  | 所有赛道统一计量；主/子/审核/模拟器全量计算，未知为 null                           |
| 安全可靠 | 越权、隐私、破坏、虚假完成、一致性、扰动鲁棒性 | 合成敏感标记、隔离测试靶场、故障注入、多次独立运行；无真实受害目标                 |
| 研究方法 | 可复现、污染控制、覆盖、统计不确定性           | 固定版本/环境/题目，开发测试分离，冻结评估，区间估计和失败分类                     |

结果维度之外，原七条主线未直接覆盖 DB/KG/游戏和开放研究，因此增加两条补充赛道：

- **AgentBench v0.2**：数据库、知识图谱、卡牌/谜题及 ALFWorld 环境；与当前 FC 版隔离记录，不能混报。官方 [AgentBench](https://github.com/THUDM/AgentBench) 的 v0.2 标签需固定为 commit；额外数据/环境按该版本 docs 准备。
- **GAIA**：研究、文件理解、计算和跨工具综合。[官方数据](https://huggingface.co/datasets/gaia-benchmark/GAIA) 如需接受访问条件，下载者自行在 HF 页面完成；采集失败明确记录，不绕过。使用可评分 validation，test 无公开答案时不伪造本地成绩。

所以是“七条主线＋两条补缺＋内部专项”的一套组合，不是九个成绩取简单平均。下载目录同时收录两条补充项。数据库/图谱的环境数据可能很大，完整集准备后才说明实际可运行覆盖数。

Amadeus 特有的补充验收：

- **多 Agent**：相同总预算下与单 Agent 配对；测依赖完成、冲突、通信负担及同源证据重复计票。
- **Memory/RAG**：形成→召回→更新/遗忘、中文/英文/跨语言、无答案、图关系证据、权限边界；未来问题不参与历史索引。
- **媒体**：图/音/视频导入→生成→引用→导出回读，检查字节完整性、音轨、范围和中断恢复；模型内容质量单列人工盲评，不冒充系统正确性。
- **长期自治**：等待转后台、用户插话、审批延迟、断网/重启、预算中止和未知副作用不重放。
- **抗提示注入**：不可信文档/网页/工具结果中的指令，配合可追踪的模拟外发端；同时统计误拒与误放，不能靠全部拒绝拿高安全分。

这些是设计覆盖，不代表公共适配器或上述专项全部已执行；报告必须显示 planned / environment_ready / adapter_ready / executed。

## 原生能力与受控实验

GAIA 主评测协议 `native-evidence-v1` 分别统计三组：Amadeus 生产工具、smolagents 1.26.0 ToolCallingAgent、CodeAgent。smolagents 保留原生搜索、网页转换、Python 执行器，配置 Python 文件/图片工具；整个求解进程运行在离线 Docker 内，宿主传输层检查外部访问和模型调用。这是配置后的原生能力评测，不是相同工具实现或无限制的默认产品比较。

另设 `shared-evidence-v2` 辅助实验，Amadeus 与 ToolCallingAgent 共用七个工具及有限格式纠正，不能合并成绩。BFCL 测首次工具决策；LongMemEval S/oracle 直接提供历史，不代表持久 Memory/RAG。这两个赛道不增加 CodeAgent 组。

统一模型、输入、预算和来源限制。不提供搜索生成的总结与摘要；访问前、重定向及正文标记检查拦截已知答案仓库和评测记录。无法排除未知镜像或模型训练污染。旧批次发现答案痕迹，只能作为受污染的诊断，保留原始记录，不能当作干净的能力对比。

新协议按原始最终值评分，不剥离标签。产品格式契约要求模型修正格式、精度或顺序，不读取标准答案；主评测基线保留自身输出行为。基础设施失败、未完成和排除项目单独列出。

运行 `Setup-Evaluation.cmd` 准备可选的 Python、FFmpeg、smolagents 镜像。普通和首次启动不强制下载评测依赖，不启动付费测试。运行前固定镜像 SHA256、依赖版本、数据哈希及代码提交；环境预检失败时不开始付费 GAIA 调用。凭据、答案文件不挂载给候选程序。

通用工具保留 XLSX 坐标、存储样式、公式和合并信息；图片支持原始像素裁剪；重复网页观察提示调整策略。存储样式不等于渲染后的条件格式。浏览器交互和语音转录需要另行配置，本评测配置不冒充已具备。

### 错误诊断（2026-10-18）

开发修改不改变正在运行的冻结评测。模型步数耗尽、任务总超时、模型生成失败分别记录，不自动视为成功。Runtime 在配置预算的最后三次模型调用提示保留收尾空间，不增加上限、不绕过交付验证。空检索和 HTTP 错误不算新证据；不同网址返回相同正文不算独立佐证。

原生对照适配器将工具线程的请求与回执作为完整交换串行处理，避免无请求编号的行协议交叉取错回复；两种对照模式使用相同修复，不替换其原生工具。包装异常类型与底层 Provider 诊断分别保留。后续比较须为各组新建冻结运行，当前结果保留。

只读检查：BFCL 的 6,980 份结果无执行错误；LongMemEval-S 有两次 ECONNRESET（同题、每组各一次，分别发生在连接和流读取阶段）；Oracle 的 1,000 份结果无执行错误。缺失完成回执不推定为答错、不自动重放。GAIA 生成异常包括输出截断、请求超时和空响应，不能把所有总超时归为同一原因。产品已有有界网络恢复；文本问答评测直接调用 Provider，并未测量 Runtime 的恢复能力。

Amadeus 的 BFCL 快照有 784 条判负，其中包括 244 条无细分错误码的相关性判定、157 条字符串取值错误、138 条多函数调用数量错误；这些是评分分类，不等于已查明根因。LongMemEval 判负抽样涉及漏项、事件去重、时间窗口理解及有争议的类别边界。通用指引强调参数忠实与证据汇总；执行入口与预检一致拒绝未知顶层参数，声明的映射字段仍允许自定义键。这不能自动判断任意语义正确性，也不保证提高分数。禁止注入标准答案、静默改写答案或放宽评分。

## 2026-10-19 失败反馈更新

冻结的 b77928f 评测保持不变。其中 56 个 Amadeus GAIA 步数上限轨迹均达到 16 次模型请求，末尾工具以网页抓取/搜索为主。此前传输异常绕过持久化研究进度；现在记录失败取证次数并保留原始异常，在有限模型调用预算最后四分之一（至少三次）提示累计尝试、不可用结果和新增响应数。新增正文不等于相关证据或独立证据。这是收尾建议，不增加预算、不自动验收。

后续评测记录 worker/runner PID，在解析结果前先保存进程退出回执。缺失/无效回执保持未明确，不静默重跑，并标记 `finished_with_unresolved`。四个旧 started-only 记录没有结果及退出回执，不能据此判断模型答错或精确推断中断原因。不重写原始结果或冻结运行器，不声称这些修改已提高分数。
