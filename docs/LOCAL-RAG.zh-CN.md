# 本地检索

## 安装

可选 Python 服务提供 E5 small/base/large（384/768/1024 维）、BGE cross-encoder 重排、FAISS、嵌入式 Qdrant、LightRAG。保留内置 SQLite FTS 与混合检索。Milvus 需独立部署服务端。

联网运行 Setup-Local-RAG.cmd，再运行 Start-Local-RAG.cmd。Windows x64、Python 3.11 的离线安装：

```powershell
./Setup-Local-RAG.ps1 -Python C:/Path/python.exe -OfflineBundle D:/Path/Amadeus-offline
# NVIDIA GPU：
./Setup-Local-RAG.ps1 -Python C:/Path/python.exe -OfflineBundle D:/Path/Amadeus-offline -Gpu
```

离线包须包含 wheelhouse、constraints.txt、models 下的两个模型目录。GPU 另需 wheelhouse-gpu 和 constraints-gpu.txt。不要复制虚拟环境。只向 .data/retrieval-python 安装，不修改系统 Python。启动使用 UTF-8，不修改执行策略。

在设置中先保存其他改动，再选择本地模型绝对路径、模型身份、提取连接和范围。配置变化后重启检索服务。普通启动会拉起已配置的服务；普通首次启动不会强制安装这些大依赖。

## 数据边界与检索

embedding、重排在本机运行。LightRAG 使用本机 JSON、NetworkX、NanoVectorDB；实体抽取及整理把所选正文发送给已配置的生成模型 API。应单独授权目标范围，不替主模型生成最终答案。

长文本使用重叠窗口和归一化均值，并添加 query/passage 前缀；避免仅截取开头，但不等于原生长上下文模型。维度更换需要重新建立向量。

融合后 cross-encoder 最多重排 60 条候选，分数不是校准概率；阈值应使用中英样本评测。

FAISS 支持 flat/HNSW/IVF-flat/IVF-PQ；样本不足回退 flat（IVF/PQ 训练下限分别 2496/9984 条，PQ 另要求维度兼容）。原生库在有时限的独立进程执行，崩溃或超时明确报告精确回退。成功建立的原生索引按向量内容哈希持久缓存，最多保留四代。嵌入式 Qdrant 是精确检索，不是服务端 HNSW。

适配器按查询传送授权范围的向量快照（最多 80 MiB float32 数据、128 MiB 请求、20 万条），不是百万向量流式索引。外部旧集合仍需保留清理策略。安装 Milvus 客户端不等于安装服务端。

LightRAG 持久记录批次 ID，结果未知不盲目重放。即使本地图保留旧数据，引用也必须匹配当前授权分块及原文。检索不等于验证。

inspect_retrieval_status 提供范围内总量、向量覆盖与维度、诊断状态；索引建议不是切换或重建授权。investigate_knowledge 支持有界多查询调查。

## 统一安装与模型管理

离线包仅为可选安装来源。Setup 将 Python 依赖安装到应用数据目录，并将模型准备到 retrieval-service/models；没有本地来源时从 Hugging Face 下载，重新运行会复用已完成的下载。本地模型复制并通过 SHA-256 校验后才更新配置，后续启动不依赖离线包；安装成功前保留原文件。在线 GPU 安装支持 -Gpu，并可用 -TorchIndexUrl 指定与驱动兼容的 PyTorch 源；默认使用 CPU。下载失败保留已有数据。

## 损坏向量容错

知识检索逐条校验已存向量：JSON 与对象结构、有限数字、非零且有限的范数、模型及查询维度。损坏或不兼容的条目不会拖垮正常语义候选；对应正文仍可通过词法检索返回。查询 embedding 失败时明确降级为词法检索；取消操作和数据库故障仍传播，不伪装成查无结果。

混合检索结果和检索轨迹包含各自的 retrievalDiagnostics，记录扫描、可用、损坏和不兼容数量；并行请求不混用诊断。正常文档索引不再只认模型名，损坏向量会重新生成，也不能被当成可复用缓存；索引状态增加 invalid 数量。记忆向量缓存复用相同校验，只对这类派生记录的 RECORD_CORRUPT 容错，不吞掉普通数据库故障。维度不兼容在查询时跳过，不自动迁移模型或重建整个语料。外部 ANN、重排、LightRAG 服务故障不在此策略下统一隐藏。

### 查询通道与单条片段来源

`retrievalDiagnostics` 提供整次查询的 embedding 模型、维度、语义通道状态、候选数量和返回通道数量。片段的 `retrievalChannels` 和 `ranking.embeddingModel` 仅描述该片段：某条结果只有词法命中，不代表整次查询没有向量参与。语义状态区分主动关闭、策略关闭、未配置、embedding 或后端失败、没有兼容候选、索引变化及已执行检索。两路都命中的结果在返回计数中会重叠。大库流式路径与小库统一使用从 1 开始的 RRF 排名：1/(60+rank)。向量参与及重排分数不保证相关性，同词异义仍可能产生无关候选。本次不需调整启动项或安装依赖，重启主服务后生效。

修复大库结果转换时遗漏 scope 的问题：此前语义候选虽然计算成功，却可能因缺少范围信息被最终权限过滤剔除。现在保留数据库中的范围，仍严格执行权限过滤。

### 文本编码与旧导入修复

文本解析严格支持 UTF-8（含 BOM）、带 BOM 的 UTF-16 LE/BE；无 BOM 的 UTF-16 仅在交替空字节提供充分依据时识别。无效 UTF-8 可以回退到严格 GB18030，兼容常见 GBK 中文文件。大量替换字符或异常控制字符会被拒绝，不再默默建立乱码索引。编码识别不是万能的：无法确定的旧编码与 UTF-32 应转换为 UTF-8。不会改写用户原文件。

重启主服务后，已开启的文件夹自动维护会对旧文本来源做一次已存正文质量检查。可疑来源即使文件哈希未变化也会重新解析、保留版本，并沿用现有已授权流程建立索引；正常文档与向量继续复用。修复失败会让损坏的当前版本退出检索，并记录逐文件问题，历史版本仍保留。这项迁移适用于已登记文件夹来源，手动上传文档需重新导入原文件。已授权的图谱抽取也可能对修复后的正文重新执行。本次不增加依赖，无需修改启动脚本、重跑首次安装或下载新向量模型。

### PDF、Office 与 OCR 正文质量

所有文档解析器会检查提取后的正文，而非仅看解析是否正常结束。只有 PDF 页码标签、OCR 标头而没有识别正文、只有格式没有单元格值的表格，以及大量替换字符或异常控制字符，都不会被当作成功导入。开启 OCR 时，PDF 文字映射损坏的页面也会尝试 OCR；仍无法恢复的乱码会给出具体页码错误。知识库上传与文件夹导入一样请求 OCR。允许正常文档夹带空白页。这些检查发现的是结构性问题，不能证明 OCR 语义正确：看似正常的错字、布局与表格顺序、已有大量文字页面中的图片文字遗漏仍需核验。已有 PDF／Office 文档不会因本轮文本编码迁移而全部重解析。

## 长程阅读与有边界的假说比较

面对有歧义、需要跨来源分析的问题，Agent 可发现 `create_research_case`、`read_knowledge_context`、`inspect_research_case`、`update_research_case` 和 `investigate_research_gap`。简单查询不需要这套流程：`search_knowledge` 不再因为包含“推断／比较”等词自动扩搜；显式 research 模式扩大当前查询的候选选择，不机械追加三条查询。

研究记录保存竞争解释、支持／反对片段、缺失观察与可区分不同解释的预测。阅读笔记可记录时间线、关系、反复出现的模式、约束或摘要，关联原始分块 ID，并区分观察、转述与推断。按顺序浏览原文开头、扩大相邻分块上下文，不需要 embedding 调用；这不是自动识别章节边界，也不是自动生成整本书摘要。回读上下文或文档时传入 caseId，将返回的证据纳入记录。截断片段会明确标注，不登记为完整阅读证据，可用文档回读获取完整片段。

研究记录仅在原对话／任务树和兼容知识范围内共享。文档版本、内容哈希和历史时点绑定证据；来源变更或删除会提示失效。需要先显式移除比较中的失效引用，再读取替换证据。同文片段按哈希去重，不同哈希也不代表独立作者。笔记仍是模型判断，不会自动变成已确认的长期记忆。

### 停止条件

以下是宿主默认策略，不需要用户逐项配置，也不代表找到了最优证据：

| 边界         | 研究记录中的行为                                                                   |
| ------------ | ---------------------------------------------------------------------------------- |
| 取证次数     | 最多 6 次尝试，成员共享                                                            |
| 单次截止时间 | 180 秒；超时后的下一次尝试最多 300 秒                                              |
| 累计取证时间 | 12 分钟，下一次截止时间不超过剩余额度                                              |
| 无新增证据   | 两次成功查询都没有新增片段哈希后停止                                               |
| 服务故障     | 与无证据进展分开计数；连续两次失败后停止并报告服务问题                             |
| 阅读预算     | 最多 16 个登记窗口／页、累计返回 16 万字符，成员共享                               |
| 重复操作     | 拒绝重复的成功查询及同一成员重复读取未变窗口；同一任务树的相同问题复用已有研究记录 |

截止时间依赖检索后端响应取消，JavaScript 定时器不能强行终止同步本地计算。失败消耗次数和时间，但不能证明没有证据；失败查询可在剩余预算内显式重试，不自动循环。执行成员已停止的待完成取证会标为中断，不重放，并标注保守估计的耗时。研究流程之外的普通查询仍可用于其他任务，这些限制不是对所有检索的全局封锁；Agent 不应通过改名新建相同研究绕过预算。

已有材料足以说明关键区别，或无法区分解释时，可以提前结束。预算耗尽要报告覆盖缺口，不强行选出赢家。新增片段本身不证明推理质量提高。开放／未定论研究只产生非阻塞交付提示，不会为了清除提示强迫继续搜索。如目标要求通读，需要另行规划覆盖范围；本流程不声称读完大库。

需要交叉质疑时，在 `submit_team_proposal` 中关联 `researchCaseId`。复核者需指出替代解释、可区分的观察及其对结论的影响；关联比较或来源变化后，原接受状态失效。沿用方案回应、修改与复核流程，简单工作不强制建队或增加消息。本轮证据接口以已索引知识片段为基础，不是覆盖网页和实验的万能验证器。

无需新增模型、安装依赖、重建索引或修改启动脚本；后续重启才加载新代码。这些机制已有回归测试，不代表文学解释或通用推理成绩已实测提高。

命令行抽取连接选择不偏向厂商：显式 `--profile` 优先（未知 ID 或不兼容协议报错）；未指定时保留旧抽取配置，新配置优先兼容的默认连接或唯一的 OpenAI Chat 连接。无法唯一确定时提示并保留抽取未配置，embedding/重排仍可用。配置过程不发送语料。显式指定连接会替换旧抽取连接；更换 embedding 模型时不再沿用旧离线模型目录，除非再次明确指定。

### 查询延迟与缓存

检索 trace 的 `diagnostics.timingsMs` 分别记录词法、查询 embedding、流式向量查询、文档图、LightRAG 与重排阶段（仅记录执行的阶段）；总耗时不能直接解释为向量库过大。统计工具中的 `vectorHealth.scanned` 在缓存命中时是构建时统计，不表示本次重新扫描全部向量。

查询 embedding 与完全相同输入的重排分数采用最多 64 项、120 秒的进程内缓存，并合并相同的并发请求。不同调用者取消互不干扰；全部取消会中止共同请求。连接、模型、凭据、查询或候选正文改变会使用新键；不缓存整份搜索结果，不跳过范围/版本校验，不在磁盘保存查询缓存。缓存不会减少候选数或禁用重排。

兼容服务可用 `/vectors/search-batch` 一次查询最多 64 个已有分片，FAISS 保持原生进程隔离但每批只启动一次 Python；旧服务回退逐分片协议。FAISS 磁盘索引按 512 MiB 预算回收而非仅保留 4 份，内存仍限制 2 份索引。Qdrant 在成功写入并核实数量后复用内容寻址集合，减少重复 upsert；部分失败、集合删除或数量变化会重新补齐。Milvus 路径尚未采用该集合写入优化。

离线随机向量微测（4 分片、每片 64 条、16 维 HNSW）逐分片约 1.294 秒，批处理约 0.307 秒，排名和分数相同。这不是生产大库端到端性能承诺；冷启动、模型装载与长候选重排仍可能占主要时间。启动脚本会检测代码变化；已有本地 RAG 进程需在空闲时重启才会使用新的 Python 实现。

### 请求超时诊断与文档图延迟

本地服务在推理前检查每个分块加前缀、重新分词后的长度，必须符合已加载模型的有限输入上限。用于分窗的全文 token 计数不等于模型实际输入；不会截短或删除原文件。重排也检查模型真实长度限制。

无正文诊断写入 `.data/retrieval-service/requests.jsonl`，每 1 MiB 轮换，仅保留一份上一轮文件。记录请求 ID、阶段耗时、输入长度和上限、结果状态，不记录正文、凭据、URL 或向量。客户端区分主动取消、截止时间和传输故障；同一请求 ID 可关联本地服务的排队、加载、分词、推理耗时。断连后不再重复发送错误响应。已超时请求在下一批模型计算前退出，已执行中的原生模型批次不会被强制杀死。HTTP 可并发接收，但模型锁仍控制推理资源占用。

分块表新增 `(document_id, ordinal)` 索引，同时加速相邻段落读取。文档图在每次查询中复用可见关系和同一引文的核验，下一次查询仍重新校验权限、有效时间与原文变化；事件证据按 ID 读取，避免加载整段会话。服务启动自动建索引，不需要重新生成向量；不会删除资料。RAG 启动器同时校验主脚本与辅助模块版本。

独立快照实测：90,108 个分块、379 条关系，同一文档图查询旧实现 31.870 秒，新实现 0.014 秒，完整返回结果一致（该查询没有匹配路径）。这是图阶段耗时，不是端到端保证。另用现有离线模型在 CPU 上验证中英日 3,732 个源 token、9 个窗口，实际张量最长 485 token，上限 512；冷加载 8.282 秒，随后推理 0.312 秒。受控排队超时返回 504，未进入推理；客户端主动断开记录为 `client_disconnected`，没有重复堆栈。无关联 ID 的历史断连无法事后确定原因。

同步文档图全表扫描会阻塞同一 Node 进程的上下文页面请求，索引修复针对该实测瓶颈；页面一直加载不等于前端故障。自动维护的 `processing` 也可能只是扫描、哈希检查，应结合阶段与导入／复用数量判断。缓存向量覆盖统计不是每次查询扫描量。PDF/DOCX 不删除，重复片段不能当独立佐证，未检索到也不能证明全库不存在。

扫描诊断区分当前周期与上次完成的扫描；processing 本身不代表新增导入或写入向量。比较数量时须核对范围、asOf 与观测时间，不能把历史 trace 当成当前增长。未变化文件跳过解析，已完成索引的维护任务不读取或改写向量。缓存 HNSW 分片的覆盖数量不等于每次查询逐条计算的向量数量。

大库统计和索引状态的 HTTP／工具请求每 64 行让出执行时间，避免向量检查独占服务主线程；这改善页面响应，不代表模型推理本身变快。LightRAG 是独立的按需启用通道，建图任务和 API 费用与内置证据关系图分别计算。

LightRAG 查询失败会保留原有范围内检索结果，并记录 lightRagStatus=unavailable 与耗时。连接启用不等于建图完成，覆盖程度需要另行查看同步任务。

冷启动恢复向量分片时，先通过局部覆盖索引选出有限数量的合格 ID，再读取该页向量，避免每批都对全范围的大体积向量 JSON 排序；范围和文档有效时间过滤继续保留。

LightRAG 重复内容项仅在原记录处理完成且正文去除首尾空白后完全一致（与 LightRAG 的保存方式一致）时计为完成。未知任务可核对原请求摘要与已保存的文档状态恢复完成状态；该核对不重新提交抽取、不重复调用模型。资料缺失、已改变或尚未完成时仍保留未知状态。

若 LightRAG 将重复项保存为新 ID，则按提交时的准确来源定位重复记录，再核对原记录已完成且正文一致；仅文件名相同不能视为成功。

### 共享分词器并发与核对后恢复

Embedding 分窗、重排长度检查、推理和 LightRAG 分词适配器使用同一模型锁，每个推理小批次结束释放；不锁住联网抽取或整批建图。这样避免快速分词器的截断、补齐状态被并发修改。HTTP 与抽取仍可并发，但暂不保证检索优先调度。

经本机令牌认证的 `POST /lightrag/documents/resume` 仅供核查后的显式恢复：传入 `jobId`、准确的原提交 `original` 和 `confirmRetry: true`，原请求摘要必须匹配。恢复核对已保存来源与正文未变化，拒绝夹带其他未完成资料，采用 LightRAG 原生的单次人工恢复协议，保留已完成记录与抽取缓存，不重新上传文档、不自动重试未知任务。失败文档尚无缓存的部分仍可能调用抽取模型；再次失败保留未知状态等待核查。该入口不加入自动扫描重试。

知识库页面单独显示 LightRAG 建图进度：已确认完成的正文分块 / 当前有效分块总数。按每个确认完成的正文分块增加进度，不等同于文件扫描、普通向量索引任务或实体数量。页面读取进度缓存并发起有界的后台状态检查，不触发建图或向量扫描；同时显示最近状态更新时间，未知结果要求检查恢复，连接失败保留上次计数。

建图进度每两秒查询有界的批次状态，不阻塞页面请求；每个确认完成的正文分块立即计入进度，其他分块失败不抹掉已完成量，整批核对后才推进下一批。抽取网络临时错误最多重试一次，认证及格式错误不重试。本地限量诊断只记录异常类型、原因类型、HTTP 状态与耗时，不保存正文和密钥。
