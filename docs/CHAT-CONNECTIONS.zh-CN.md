# 接入聊天

[English](CHAT-CONNECTIONS.md) | [简体中文](CHAT-CONNECTIONS.zh-CN.md)

左侧栏“设置”下面新增“接入聊天”。连接随 Amadeus 服务启动，默认关闭，保存并启用后才接收消息。不需要新增启动脚本，不自动安装桥接程序、不修改防火墙。关闭浏览器后服务可继续工作，电脑关机后不能继续。

## 配置步骤

先创建专用会话，选好模型、工具、文件范围和权限，再添加连接并填写平台凭据与可信私聊用户 ID（不是昵称）。一个连接绑定一个会话与一个私聊联系人，暂不开放群聊。该联系人可通过 Agent 使用这个会话已有的历史和授权资源。模型或范围发生变化后连接暂停，重新核对并保存才恢复。变更账号、接收人、地址或会话需要新建连接，不能把待发结果改投另一个人。

| 平台         | 协议与必填内容                                                                                                              |
| ------------ | --------------------------------------------------------------------------------------------------------------------------- |
| Telegram     | 官方 Bot API 长轮询；Bot Token、私聊数字用户 ID。不要让其他程序同时消费同一机器人的更新。                                   |
| WhatsApp     | 官方 Business Cloud API，不是个人号扫码；访问令牌、Phone Number ID、Graph API 版本、App Secret、自定 Webhook Verify Token。 |
| VK           | 官方社群长轮询；社群令牌、社群 ID、API 版本、私聊数字用户 ID；社群后台启用消息与长轮询事件。                                |
| QQ 官方      | App ID、服务令牌栏填 AppSecret、联系人 openid（不是 QQ 号）、签名 Webhook；遵守平台审核与权限要求。                         |
| 企业微信     | 官方智能机器人 WebSocket；Bot ID、secret、私聊 userid。与个人微信不同。                                                     |
| QQ 桥接      | 另行配置可信 OneBot 11（如 NapCat），填写本机 WebSocket 地址、访问令牌、机器人 QQ 号、私聊 QQ 号。                          |
| 个人微信桥接 | 另行配置兼容 OneBot 12 的桥接服务、机器人 ID 与用户 ID；受客户端版本及上游维护限制，不自动降级微信或绕过登录验证。          |

WhatsApp、QQ 官方接入需要 HTTPS 反向代理，仅代理独立回调端口（默认 8788），路径保存后显示。**不要把 Amadeus 管理端口暴露到公网。** WhatsApp 验证原始请求体 HMAC，QQ 验证 Ed25519 签名与时间戳。令牌在设置中只写不读，编辑留空保留原值，独立私有文件保存，Windows 使用 DPAPI。

## 消息、审批与多媒体

普通消息按收到顺序排队，不会带出本机输入框草稿。`/status` 查询状态；`/stop` 停止当前会话任务并取消尚未处理的远程消息。推荐专用会话，避免停止本机正在做的其他工作。

远程审批默认关闭。启用后，适合远程复核的操作会显示完整审核内容，附一次性 `/approve CODE`、`/deny CODE`；问题使用 `/answer CODE 回答`。只有绑定用户可答，15 分钟有效，操作内容改变或已回答后失效。敏感、过长及副作用恢复核对仍留在本机。不能远程更改永久权限；普通“同意”不会自动批准操作。

图片、语音/音频、视频、文档进入现有附件与媒体能力。语音转写使用已配置的服务；企业微信提供的转写明确标注为平台转写。图片、视频理解仍取决于模型和工具是否就绪，收到文件不代表已经理解。远程任务生成的媒体及登记交付的文件可以回传原私聊；不会扫描工作区或发送其他本机任务的产物。

支持的平台尽量使用原生图片、音频、视频消息。VK 当前按文档附件回传；企业微信音频按文件发送，不把 WAV 冒充语音编码。平台不支持的格式会显示发送问题。这不是实时语音或视频通话，同相册的独立消息目前分别处理。

当前受控传输通道每消息最多 10 个附件，每文件最多 50 MiB；Telegram 下载最多 20 MiB，文档解析最多 25 MiB。平台格式、编码、回复窗口和账号额度限制同时生效。下载只接受公开 HTTPS，固定解析后的地址，不跟随重定向，不访问内网地址或本机路径。大文件仍可在本机取用，暂不承诺任意大小视频跨平台发送。

QQ 被动私聊回复窗口或次数耗尽时，待发结果保留，等待联系人再发一条消息。其他平台失败显示在投递状态中。网络断开或服务重启造成“可能已发出”的消息不会自动重发；在“接入聊天”核对后选择重发或忽略，避免重复。附件导入失败不会启动一个假装读过附件的纯文本任务。

## 验证与来源

本地测试覆盖七种协议输入、签名及过期请求、绑定账号、队列、附件隔离、一次性审批、产物登记、模拟媒体回执、重启状态、附件解密和内网地址拒绝。**未提供真实账号凭据，尚不能宣称各平台真机收发都通过。** 桥接协议实现不等于捆绑或官方认可第三方客户端。测试不调用付费模型。
