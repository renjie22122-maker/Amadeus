# 接入聊天

[English](CHAT-CONNECTIONS.md) | [简体中文](CHAT-CONNECTIONS.zh-CN.md)

在侧栏“接入聊天”配置。连接随 Amadeus 服务启动，不需要新增启动项；浏览器关闭后服务仍可运行。更新版本需在合适时间重启 Amadeus，保存源码不会改变正在运行的服务。桥接程序需要独立运行，不自动修改防火墙。

## 普通聊天与远程工作

新连接默认普通聊天：选择的会话只作为模型配置模板，创建全新的独立会话，不复制历史、项目目录、私人记忆或技能。可使用网页、媒体以及可选的普通对话共享知识库；禁止命令、任意文件读写、MCP、子代理和私人记忆工具。共享知识库可能包含私人资料，开启意味着回答可能向接收人或全群公开引用。不能靠群消息把普通聊天升级为电脑操作。

远程工作必须单独选择已有专用会话及授权成员，沿用其历史、资源和权限。旧版连接保留原工作模式，不静默迁移。账号、会话、接收人、地址或模式改变要新建连接；模型和资源范围变更会暂停连接，核对并保存后恢复。同一账号的同一私聊/群不能同时绑定两条路由。

## 群聊

选择“群聊”，填群 ID、控制人 ID；选择明确的允许成员，或在普通聊天中开启“所有群成员”。同群共享讨论上下文，每条消息携带实际发送者 ID；不同群、私聊、本机私人会话相互隔离。昵称、空白名、改名不改变授权身份。引用内容只是资料，不能替被引用者授权。

- 默认使用 `/amadeus 问题`。OneBot 的真实 @ 片段和 QQ 官方群 @ 事件也可触发；其他协议目前使用前缀，不保证所有平台的 @ 或回复消息识别。
- 可开启近期群上下文：最多保留 40 条观察、每条 600 字符，24 小时过期；查询取最近 30 条。只有允许成员的消息进入，媒体不因旁观而自动下载。此限制不截断显式提问的正文。
- 可选择“适度参与”：安静至少 5 秒后对最近两分钟内的新消息做判断；两次判断至少间隔两分钟，每小时最多三次，包括选择沉默的判断。没有新消息不调用模型；有显式任务/附件在排队时优先处理。判断会消耗模型额度，并非免费后台监听。
- 主动判断允许保持沉默，不能执行电脑操作、生成媒体、启动子代理或创建定时任务。它不保证每个明确提问都被识别，重要问题请 @ 或使用前缀。
- 自己发出的消息不参与。Telegram 可识别的其他机器人消息被排除；桥接平台不能可靠识别所有机器号，因此仍依靠冷却和预算防止互相接话。
- `/amadeus /status`、`/amadeus /stop` 和审批仅认控制人。工作群不能开放全员操作，其他授权成员也不能代控制人审批。

### 控制人邀请后自动开放

在 OneBot 11 私聊控制连接开启“指定控制人邀请入群后自动开放基本聊天”。只接受认证桥接连接的 `group_increase / invite` 通知，要求机器人、入群账号、实际邀请人和时间均匹配。新群创建普通聊天独立会话，允许全群基本聊天，开启近期上下文和适度参与，继承共享知识库开关，绝不继承工作权限；发送一条群内说明。

其他人邀请、加群申请批准、缺少邀请人字段、旧事件或消息文本自称邀请都不自动授权。已存在的群（含暂停群）不会重新开启。此功能处理**已入群通知**，不代表自动批准所有加群请求。开启之前已加入的群请在界面手动创建普通群连接，不根据历史聊天猜邀请人。连接总数保护上限为 20，达到上限需本地整理。

## 各平台配置

1. **Telegram**：在官方 `@BotFather` 创建机器人并取得 token。用平台更新中的 `message.from.id` 作为控制人 ID，`message.chat.id` 作为接收聊天 ID；群通常为负数。需要全群上下文时，检查 BotFather 的群隐私模式及群权限；服务看不到的平台消息无法补齐。不要让另一个程序同时长轮询同一 token。
2. **QQ / NapCat**：另行安装可信 NapCat，登录机器人 QQ。在 OneBot 11 设置启用正向 WebSocket，监听 `127.0.0.1` 的空闲端口并设置访问令牌。Amadeus 选择 OneBot 11，填 `ws://127.0.0.1:端口`、该令牌、机器人 QQ、控制人 QQ。群连接再填群号。QQ 密码不是服务令牌，不把桥接端口暴露公网。邀请人校验使用数字 QQ，和昵称无关。
3. **QQ 官方机器人**：在 QQ 开放平台创建机器人，服务令牌栏填 AppSecret，账号栏填 App ID，配置签名 Webhook。用户和群使用平台事件里的 openid，不能填普通数字 QQ 号。群消息能力受官方权限和 @ 事件范围限制。
4. **企业微信**：使用官方智能机器人 WebSocket 配置的 Bot ID 与 secret；控制人填事件中的 userid，群填 chatid。旧式群 Webhook 地址不是此协议，也不等于个人微信登录。
5. **个人微信桥接**：需要另行运行兼容 OneBot 12 的可信服务，填其回环 WebSocket、token、机器人 user_id、联系人 user_id 或 group_id。桥接项目及微信版本兼容性需自行核实；Amadeus 不内置微信客户端，不自动降级或绕过登录。
6. **VK**：在社群管理中取得具有消息权限的社群 token、社群 ID，开启消息与 Long Poll。填支持的 API 版本；用户 ID 为实际 from_id，群会话使用事件中的 peer_id，不能拿群标题代替。
7. **WhatsApp**：使用 Meta Business Cloud API，不是个人号扫码。填访问 token、Phone Number ID（不是电话号码）、Graph API 版本、App Secret 和自定 Verify Token。控制人/接收人使用事件中的用户号码 ID；当前适配器只支持私聊。

QQ 官方和 WhatsApp 需要 HTTPS 反向代理到独立回调端口（默认 8788），仅暴露保存后显示的回调路径，不能暴露 Amadeus 管理端口。令牌编辑留空保留原值，Windows 使用 DPAPI 保存。

## 多媒体、审批与恢复

显式任务的图片、语音、视频和文档进入现有附件链；能否理解取决于模型及转写等依赖。仅回传该连接运行登记的产物，不扫描工作区。普通聊天也可请求媒体生成，仍遵守服务费用及审批策略。VK 以文档回传，企业微信音频可能作为文件发送，不伪装编码。

远程审批只在工作模式显式开启：控制人用一次性 `/approve CODE`、`/deny CODE` 或 `/answer CODE 内容` 回答，15 分钟有效；操作变更后失效。敏感、超长或恢复核对留在本机。群内审批内容会被其他成员看到，建议敏感工作使用私聊。

每条消息最多 10 个附件，每文件最多 50 MiB；Telegram 下载最多 20 MiB，文档解析最多 25 MiB，并受平台限制。下载只接受经过地址校验的公开 HTTPS，不读取桥接消息声称的本机路径。附件失败不假装已读取。

同账号多群共用连接并分别排队投递；不确定是否已发送的结果不自动重发。暂停会取消待处理消息，删除连接会清理近期群观察。已进入正常会话历史的内容按会话历史保留，不等于 24 小时自动删除全部聊天。远程消息和定时任务不会带出本机输入框草稿。

## 验证与来源

自动测试覆盖协议、隔离、成员权限、邀请真实性、重复事件、上下文容量/过期、限频、静默结果和共享投递。测试不调用付费模型。真实 QQ 私聊收发和群消息到达已验证；新增群行为仍需部署后验收，其他平台不宣称真机全通过。

参考：[Telegram](https://core.telegram.org/bots/api)、[Meta](https://developers.facebook.com/docs/whatsapp/cloud-api/)、[VK](https://github.com/VKCOM/vk-api-schema)、[QQ](https://github.com/tencent-connect/bot-docs)、[企业微信](https://github.com/WecomTeam/aibot-node-sdk)、[NapCat](https://github.com/NapNeko/NapCatQQ)、[OneBot 11](https://github.com/botuniverse/onebot-11)、[OneBot 12](https://12.onebot.dev/)。

## 发送格式

QQ、微信及当前其他适配器以纯文本发送模型回答：去掉 Markdown 排版标记，表格转成带列名的逐项记录，保留代码原文、换行、网址、脚注和公式内容；不把代码中的星号、下划线当作排版删除。转换后再按平台字节上限分段。本地会话保留原文；审批指令及待审核操作内容不经过该转换，避免改变审批对象。图片、语音和视频继续通过媒体通道发送。

## 群信息、回复目标与表情包

远程运行可用 `inspect_chat` 查看当前平台、群/私聊 ID、最近 20 条消息的发送者和附件元数据；`list_chat_members` 在 OneBot 11/12 当前群内查询姓名/群名片，支持关键词和分页。QQ 返回的 owner/admin/member 是平台角色，不等于真实身份，也不改变控制人授权；OneBot 12 未返回角色时显示 unknown。模型不能传入其他群号查询或发送。其他平台暂未接入群成员查询时明确返回不支持。

`prepare_chat_reply` 给最终回复设置真正的 @、引用消息、QQ 原生表情 ID 或当前会话的媒体引用。OneBot 11 使用 at/reply/face，OneBot 12 使用 mention/reply（取决于微信桥接端实现）；其他适配器保留纯文本及 Unicode 表情，不假装实现原生 @。仅可 @ 本群近期发言或刚查询过的成员，不支持 @全体；引用只接受当前聊天近期收到的消息 ID。分段回复只在首段加 @/引用，重复执行覆盖当前计划，不立即重复发消息。连接变化或引用过期会撤下结构化回复计划并记录本机警告。

图片型表情包、GIF 和普通图片走同一媒体通道，Agent 可读取并选用当前会话已收到或生成的素材。原生 QQ 表情使用数值 ID，不能把普通 `@名字` 或 CQ 字符串当作真正消息段。不保证不同平台将动图显示为完全相同的贴纸形式；不支持的格式应明确反馈。

## 旁听附件与群文件

群旁听只保存文字的旧实现会留下“请检查附件”占位，却没有图片字节。现在近期消息保留受限的附件元数据（每连接最多 40 条、24 小时）；模型用 `read_chat_media(messageId)` 按需导入，拿到 attachment 引用后再调用 `read_image`、`transcribe_media` 或 `read_attachment`。下载成功不等于已理解；没有视觉模型或转写服务时必须如实说明。按需导入不启动第二轮模型、不拾取本地未发送草稿、不自动回复或扩展电脑文件访问权。

QQ `group_upload` 文件通知也进入此链；支持群里新收到的文件，不代表能够列出未收到的整个历史群文件库。PDF/Word/表格/文本使用现有文档解析，图片使用视觉读取，音频需要转写。已收到文件的解析预算与失败状态仍适用。

NapCat 建议启用 `enableLocalFile2Url`，让已认证的本机 OneBot API 返回媒体 Base64 字节；这可以避开 QQ 图片 CDN 直连失败。`get_record(out_format=mp3)` 返回的转码字节优先使用，不能把本机路径当 URL 或直接交给普通聊天读取。其他桥接实现可提供字节或公开 HTTPS URL；公开 HTTP URL仅尝试升级 HTTPS，不放开内网地址。图片/音频/文件超过传输预算明确失败，不进行无限重试。桥接认证、回环绑定保持不变；无需新增 Python/模型依赖，Amadeus 重启加载新工具。

验证：新增跨群拒绝、原生消息段、群文件通知、混合消息、旁听图片导入幂等和音频转码字节测试；本机只读查询确认当前群信息及成员可得，实际取得 122,966 字节 GIF。未向真实群发送测试消息；微信等适配器依据协议测试，不宣称完成所有平台真机验证。
