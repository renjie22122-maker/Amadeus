# 接入聊天

[English](CHAT-CONNECTIONS.md) | [简体中文](CHAT-CONNECTIONS.zh-CN.md)

在侧栏“接入聊天”配置。连接随 Amadeus 服务启动，不需要新增启动项；浏览器关闭后服务仍可运行。更新版本需在合适时间重启 Amadeus，保存源码不会改变正在运行的服务。桥接程序需要独立运行，不自动修改防火墙。

## 普通聊天与远程工作

新连接默认普通聊天：选择的会话只作为模型配置模板，创建全新的独立会话，不复制历史、项目目录、私人记忆或技能。可使用网页、媒体以及可选的普通对话共享知识库；禁止命令、任意文件读写、MCP、子代理和私人记忆工具。共享知识库可能包含私人资料，开启意味着回答可能向接收人或全群公开引用。不能靠群消息把普通聊天升级为电脑操作。

远程工作必须单独选择已有专用会话及授权成员，沿用其历史、资源和权限。旧版连接保留原工作模式，不静默迁移。账号、会话、接收人、地址或模式改变要新建连接；模型和资源范围变更会暂停连接，核对并保存后恢复。同一账号的同一私聊/群不能同时绑定两条路由。

## 群聊

选择“群聊”，填群 ID、控制人 ID；选择明确的允许成员，或在普通聊天中开启“所有群成员”。同群共享讨论上下文，每条消息携带实际发送者 ID；不同群、私聊、本机私人会话相互隔离。昵称、空白名、改名不改变授权身份。引用内容只是资料，不能替被引用者授权。

- 默认使用 `/amadeus 问题`。OneBot 的真实 @ 片段和 QQ 官方群 @ 事件也可触发；其他协议目前使用前缀，不保证所有平台的 @ 或回复消息识别。
- 可开启近期群上下文：最多保留 40 条观察、每条 600 字符，24 小时过期；查询取最近 30 条。只有允许成员的消息进入，媒体不因旁观而自动下载。此限制不截断显式提问的正文。
- 可选择“适度参与”：安静至少 5 秒后对最近两分钟内的新消息做判断；两次判断至少间隔两分钟，每小时最多三次，包括选择沉默的判断。没有新消息不调用模型；有显式任务/附件在排队时优先处理。判断会消耗模型额度，并非免费后台监听。
- 主动判断允许保持沉默，不能执行电脑操作、生成媒体、启动子代理或创建定时任务。它不保证每个明确提问都被识别，重要问题请 @ 或使用前缀。
- 自己发出的消息不参与。Telegram 可识别的其他机器人消息被排除；桥接平台不能可靠识别所有机器号，因此仍依靠冷却和预算防止互相接话。
- `/amadeus /status`、`/amadeus /stop` 和审批仅认控制人。工作群不能开放全员操作，其他授权成员也不能代控制人审批。

### 控制人邀请后自动开放

在 OneBot 11 私聊控制连接开启“指定控制人邀请入群后自动开放基本聊天”。只接受认证桥接连接的 `group_increase / invite` 通知，要求机器人、入群账号、实际邀请人和时间均匹配。新群创建普通聊天独立会话，允许全群基本聊天，开启近期上下文和适度参与，继承共享知识库开关，绝不继承工作权限；发送一条群内说明。

其他人邀请、加群申请批准、缺少邀请人字段、旧事件或消息文本自称邀请都不自动授权。已存在的群（含暂停群）不会重新开启。此功能处理**已入群通知**，不代表自动批准所有加群请求。开启之前已加入的群请在界面手动创建普通群连接，不根据历史聊天猜邀请人。连接总数保护上限为 20，达到上限需本地整理。

## 各平台配置

1. **Telegram**：在官方 `@BotFather` 创建机器人并取得 token。用平台更新中的 `message.from.id` 作为控制人 ID，`message.chat.id` 作为接收聊天 ID；群通常为负数。需要全群上下文时，检查 BotFather 的群隐私模式及群权限；服务看不到的平台消息无法补齐。不要让另一个程序同时长轮询同一 token。
2. **QQ / NapCat**：另行安装可信 NapCat，登录机器人 QQ。在 OneBot 11 设置启用正向 WebSocket，监听 `127.0.0.1` 的空闲端口并设置访问令牌。Amadeus 选择 OneBot 11，填 `ws://127.0.0.1:端口`、该令牌、机器人 QQ、控制人 QQ。群连接再填群号。QQ 密码不是服务令牌，不把桥接端口暴露公网。邀请人校验使用数字 QQ，和昵称无关。
3. **QQ 官方机器人**：在 QQ 开放平台创建机器人，服务令牌栏填 AppSecret，账号栏填 App ID，配置签名 Webhook。用户和群使用平台事件里的 openid，不能填普通数字 QQ 号。群消息能力受官方权限和 @ 事件范围限制。
4. **企业微信**：使用官方智能机器人 WebSocket 配置的 Bot ID 与 secret；控制人填事件中的 userid，群填 chatid。旧式群 Webhook 地址不是此协议，也不等于个人微信登录。
5. **个人微信桥接**：需要另行运行兼容 OneBot 12 的可信服务，填其回环 WebSocket、token、机器人 user_id、联系人 user_id 或 group_id。桥接项目及微信版本兼容性需自行核实；Amadeus 不内置微信客户端，不自动降级或绕过登录。
6. **VK**：在社群管理中取得具有消息权限的社群 token、社群 ID，开启消息与 Long Poll。填支持的 API 版本；用户 ID 为实际 from_id，群会话使用事件中的 peer_id，不能拿群标题代替。
7. **WhatsApp**：使用 Meta Business Cloud API，不是个人号扫码。填访问 token、Phone Number ID（不是电话号码）、Graph API 版本、App Secret 和自定 Verify Token。控制人/接收人使用事件中的用户号码 ID；当前适配器只支持私聊。

QQ 官方和 WhatsApp 需要 HTTPS 反向代理到独立回调端口（默认 8788），仅暴露保存后显示的回调路径，不能暴露 Amadeus 管理端口。令牌编辑留空保留原值，Windows 使用 DPAPI 保存。

## 多媒体、审批与恢复

显式任务的图片、语音、视频和文档进入现有附件链；能否理解取决于模型及转写等依赖。仅回传该连接运行登记的产物，不扫描工作区。普通聊天也可请求媒体生成，仍遵守服务费用及审批策略。VK 以文档回传，企业微信音频可能作为文件发送，不伪装编码。

远程审批只在工作模式显式开启：控制人用一次性 `/approve CODE`、`/deny CODE` 或 `/answer CODE 内容` 回答，按下文的平台审批时限有效；操作变更后失效。敏感、超长或恢复核对留在本机。群内审批内容会被其他成员看到，建议敏感工作使用私聊。

每条消息最多 10 个附件，每文件最多 50 MiB；Telegram 下载最多 20 MiB，文档解析最多 25 MiB，并受平台限制。下载只接受经过地址校验的公开 HTTPS，不读取桥接消息声称的本机路径。附件失败不假装已读取。

同账号多群共用连接并分别排队投递；不确定是否已发送的结果不自动重发。暂停会取消待处理消息，删除连接会清理近期群观察。已进入正常会话历史的内容按会话历史保留，不等于 24 小时自动删除全部聊天。远程消息和定时任务不会带出本机输入框草稿。

## 验证与来源

自动测试覆盖协议、隔离、成员权限、邀请真实性、重复事件、上下文容量/过期、限频、静默结果和共享投递。测试不调用付费模型。真实 QQ 私聊收发和群消息到达已验证；新增群行为仍需部署后验收，其他平台不宣称真机全通过。

参考：[Telegram](https://core.telegram.org/bots/api)、[Meta](https://developers.facebook.com/docs/whatsapp/cloud-api/)、[VK](https://github.com/VKCOM/vk-api-schema)、[QQ](https://github.com/tencent-connect/bot-docs)、[企业微信](https://github.com/WecomTeam/aibot-node-sdk)、[NapCat](https://github.com/NapNeko/NapCatQQ)、[OneBot 11](https://github.com/botuniverse/onebot-11)、[OneBot 12](https://12.onebot.dev/)。

## 发送格式

QQ、微信及当前其他适配器以纯文本发送模型回答：去掉 Markdown 排版标记，表格转成带列名的逐项记录，保留代码原文、换行、网址、脚注和公式内容；不把代码中的星号、下划线当作排版删除。转换后再按平台字节上限分段。本地会话保留原文；审批指令及待审核操作内容不经过该转换，避免改变审批对象。图片、语音和视频继续通过媒体通道发送。

## 群信息、回复目标与表情包

远程运行可用 `inspect_chat` 查看当前平台、群/私聊 ID、最近 20 条消息的发送者和附件元数据；`list_chat_members` 在 OneBot 11/12 当前群内查询姓名/群名片，支持关键词和分页。QQ 返回的 owner/admin/member 是平台角色，不等于真实身份，也不改变控制人授权；OneBot 12 未返回角色时显示 unknown。模型不能传入其他群号查询或发送。其他平台暂未接入群成员查询时明确返回不支持。

`prepare_chat_reply` 给最终回复设置真正的 @、引用消息、QQ 原生表情 ID 或当前会话的媒体引用。OneBot 11 使用 at/reply/face，OneBot 12 使用 mention/reply（取决于微信桥接端实现）；其他适配器保留纯文本及 Unicode 表情，不假装实现原生 @。仅可 @ 本群近期发言或刚查询过的成员，不支持 @全体；引用只接受当前聊天近期收到的消息 ID。分段回复只在首段加 @/引用，重复执行覆盖当前计划，不立即重复发消息。连接变化或引用过期会撤下结构化回复计划并记录本机警告。

图片型表情包、GIF 和普通图片走同一媒体通道，Agent 可读取并选用当前会话已收到或生成的素材。原生 QQ 表情使用数值 ID，不能把普通 `@名字` 或 CQ 字符串当作真正消息段。不保证不同平台将动图显示为完全相同的贴纸形式；不支持的格式应明确反馈。

## 旁听附件与群文件

群旁听只保存文字的旧实现会留下“请检查附件”占位，却没有图片字节。现在近期消息保留受限的附件元数据（每连接最多 40 条、24 小时）；模型用 `read_chat_media(messageId)` 按需导入，拿到 attachment 引用后再调用 `read_image`、`transcribe_media` 或 `read_attachment`。下载成功不等于已理解；没有视觉模型或转写服务时必须如实说明。按需导入不启动第二轮模型、不拾取本地未发送草稿、不自动回复或扩展电脑文件访问权。

QQ `group_upload` 文件通知也进入此链；支持群里新收到的文件，不代表能够列出未收到的整个历史群文件库。PDF/Word/表格/文本使用现有文档解析，图片使用视觉读取，音频需要转写。已收到文件的解析预算与失败状态仍适用。

NapCat 建议启用 `enableLocalFile2Url`，让已认证的本机 OneBot API 返回媒体 Base64 字节；这可以避开 QQ 图片 CDN 直连失败。`get_record(out_format=mp3)` 返回的转码字节优先使用，不能把本机路径当 URL 或直接交给普通聊天读取。其他桥接实现可提供字节或公开 HTTPS URL；公开 HTTP URL仅尝试升级 HTTPS，不放开内网地址。图片/音频/文件超过传输预算明确失败，不进行无限重试。桥接认证、回环绑定保持不变；无需新增 Python/模型依赖，Amadeus 重启加载新工具。

验证：新增跨群拒绝、原生消息段、群文件通知、混合消息、旁听图片导入幂等和音频转码字节测试；本机只读查询确认当前群信息及成员可得，实际取得 122,966 字节 GIF。未向真实群发送测试消息；微信等适配器依据协议测试，不宣称完成所有平台真机验证。

### 升级前的附件记录与直接看图

旧版群上下文可能只有“请检查附件”的文字，没有媒体引用。OneBot 11 现在允许按已在当前群观察到的消息 ID 补取原消息；严格核对群 ID、消息 ID、发送者后才保存附件元数据，不接受模型任意指定的历史消息。平台已删除或过期的消息仍可能无法恢复。

群上下文逐条标明“可按需读取”“本条无附件”“旧版元数据缺失”，不能根据上下文只有文字就宣称所有图片不可读。`read_chat_media` 在当前连接声明支持视觉时直接返回最多 3 张图片的实际像素，省去再次调用 read_image 的步骤；其余图片仍可逐张读取。无视觉能力和解码失败各自明确返回状态；GIF 默认只预览第一帧。语音仍需转写，文件仍需解析。这不是强制每轮下载全群图片。

权限修复：工具发现和执行前复核都应用同一普通远程聊天能力策略，避免旧会话保存的工具清单误报 CAPABILITY_CHANGED；真实权限、工作区、远程聊天模式或共享资料开关变化仍会中止执行。测试覆盖工具执行入口，不能只凭下载字节成功判定链路完成。

可选的 Windows 启动任务和 OneBot 11 独立兜底提示见 [Bot 启动与独立状态提示](BOT-STARTUP.zh-CN.md)。

### 好友申请审核（OneBot 11）

在专用私聊工作连接上开启“将好友申请发给此控制人审批”。每个机器人账号只配置一个审核控制人；默认关闭。新好友申请转发申请人 QQ、验证消息和随机处理编号。验证消息是不可信的对方文字，不会交给模型执行。

控制人发送 `同意 编号` / `拒绝 编号`。只有一个待处理好友申请且没有待处理任务输入时，允许简写 `同意` / `拒绝`。申请保留 24 小时。也可以登录机器人 QQ 手动接受；收到对应申请的 `friend_add` 平台通知后开放普通聊天。断线期间没有收到的申请或接受通知需要在 QQ 客户端核查，不保证补回历史事件。

通过后每位好友新建独立普通会话，不复制控制人历史、项目、私人记忆、工作权限或远程审批。默认沿用控制连接的共享知识库选项，已开放资料可能在回答中引用。既有连接（含暂停的连接）不自动改权限或重新开启。接入总数 20 条上限仍适用；每天最多记录 50 条新申请。容量不足不会自动通过；桥接结果不确定不自动重试，请在 QQ 核查。

好友同意不是任务审批：操作电脑或生成媒体等已有审批仍使用准确的 `/approve 审批码`，仅绑定控制人可用。发送完整远程审批提示后，不再追加相互矛盾的“必须在电脑上处理”通知。敏感信息、过大载荷及恢复检查仍要求本机处理。

远程审批的同意／拒绝命令各自作为独立短消息发送，可长按复制整条后发送。群聊自动带触发前缀；这不是平台原生按钮。前一条消息提供精简摘要，/details CODE 可查看完整操作，审批码仍为一次性、按下文的平台审批时限有效。

### 群聊呼叫、图片旁听与定向回复

仅包含原生 @机器人的消息也作为明确呼叫进入对话，简短回应；不会因去除 @ 后正文为空而丢弃。未 @ 的图片、表情包和群文件仍保留可读取的消息记录，但不单独触发主动参与检查，也不生成“请检查附件”的伪用户指令。用户之后明确询问时仍可按原消息读取，图片关联逻辑不变。

主动参与与明确请求分开标注；当前发送者 ID 单独提供，不能把控制人／群主当成提问者。主动回复尚未交付时收到新的明确请求，会丢弃过时的主动回复。内部 `[NO_REPLY]` 标记不直接发群：主动轮保持静默，明确请求异常返回该标记时发简短确认，不声称已理解附件。

OneBot 11／12 群内明确请求的回复默认原生 @当前发送者；模型已有明确目标时保留并校验其属于当前群。主动全群发言不默认 @任何人。过期或未观察到的成员不会猜测补齐；不支持原生 @的平台不伪造显示名标签。这些边界用协议及调度测试验证，不保证视觉模型一定认出动漫角色。

远程审批默认显示操作、目标、参数、费用与风险；媒体长正文使用明确标记的预览。`/details 审批码` 可在同一控制人连接内查看完整载荷，不批准操作。命令与路径不截断，敏感内容和超大载荷仍只允许本机审核。

### 可撤销的记住授权

审批卡新增“允许并记住此范围”；远程控制人可复制 `/allow-similar 审批码`。它不是风险等级开关，也不是授权所有类似工具。媒体生成／转写采用同一服务配置范围：正文、音色、参数及当前会话有权访问的参考附件可变，单次估算费用不得增加；服务 ID、地址、模型等配置变更需重新审核。未知费用仍不提供记住选项。

其他包含明确执行后端和命令的审批采用精确参数匹配，命令、路径、参数、源码摘要等审批字段变化均重新询问。只有名称而没有执行身份的扩展审批、恢复检查、强制人工复核不支持记住。所有授权只适用于当前会话，有效 24 小时、最多 100 次；不会覆盖原有工具权限、附件隔离或执行前复核。

本地已批准卡片可撤销；远程用 `/grants` 查看、`/revoke-grants` 撤销本会话授权（群聊加已有触发前缀）。只允许已开启远程审批的工作控制人管理，普通聊天成员无权创建授权。授权保存在本机，重启可恢复，权限／工作区／连接版本变化后不能套用旧范围。撤销影响后续请求，不中止已经批准并执行中的操作。

### 审批有效期与消息撤回

远程审批采用按平台区分的应用有效期：OneBot 11/12 默认 90 秒，为桥接和撤回留出余量；Telegram 默认 5 分钟；其他适配器默认 2 分钟、暂不自动撤回。这不是宣称平台统一限制：OneBot 协议仅定义撤回动作，没有共同的撤回时限；实际受平台、账号和桥接能力限制。Telegram 另有官方删除规则。

有效期包含发送排队耗时。剩余不足 30 秒的审批片段取消发送并使旧码过期；控制人可以用 `/renew 原码` 重新获取未变化的待审批请求，不会自动无限续期。处理完毕或超时后，使用机器人实际发送回执尝试撤回审批信息。撤回未确认时保留未确认状态，不声称成功、不盲目重复。平台不支持则保留消息。撤回只影响平台显示，不删除本地对话与审计、不取消已批准操作；远程码超时也不会自动拒绝本地待审批请求。

可以在当前聊天明确要求 Bot 撤回自己的回复。`inspect_chat` 返回发送回执，`retract_chat_message` 只接受当前聊天中经过确认的 Bot 消息。普通成员仅能撤回 Bot 对自己的回复；控制人或实时查询确认的平台管理员可以处理其他 Bot 消息。目标不明确先澄清，不删除其他用户消息，不跨群。历史消息或未保存平台回执的媒体不能猜测撤回。

启动项无需增加进程、端口或依赖；正常启动自动迁移表，继续使用已有独立 Bot 启动器。部署只需在空闲时重启 Amadeus，不重启 NapCat 或 benchmark。重连后会处理过期审批，但长时间离线可能已超过平台撤回期限。

### 快捷帮助

只 @Bot 或发送 `/help`，由程序直接返回精简帮助，不调用模型。控制人额外看到状态、停止命令；工作入口已开远程审批时还会显示授权管理命令。帮助不会生成审批码。@ 加文字或媒体仍正常处理。`sentMessages` 只包含已确认的近期发送回执，升级前的历史消息、未跟踪媒体和正在生成的回复可能不在列表中；不要要求用户提供内部 deliveryId。

### 收到的语音消息自动续答

远程语音仍使用现有转写服务与审批规则。为当前收到的附件提交获准转写后，宿主保存续答记录；原轮次结束但尚未读到转写文本时，文本完成后在原聊天、原发送人权限下自动续答，无需“插入草稿”，不读取或提交输入框草稿。模型已经读过转写结果则不重复回复。连接授权变化、轮次中断、`/stop` 会阻止续答；失败或等待超过 15 分钟给出明确提示。这个机制只处理聊天入口的语音，不改变本地录音编辑流程，不免除审批。

消息里的其他成员 @ 保留 ID 与正文，不视为单独 @Bot。明确请求中模型错误返回 NO_REPLY 时，提示本次未生成有效答复，不再伪装成用户没有发送正文。

### 群媒体一次授权

在普通群聊配置中，由本机管理员开启“群媒体授权”，选择服务、单次估算
费用上限和全群每小时次数，保存一次后，获准聊天的成员无需逐次审批即可
使用这些媒体服务。它不开放远程工作、命令执行、私人文件、配置修改或群

默认仅允许估算费用为 0 的服务，每群每小时 12 次；费用未知不能预授权。

NapCat 快捷启动可在本地 bot 配置中设置 `bridgeWebUiConfig`，指向 NapCat 的 `config/webui.json`。Bot only 启动器读取当前 Token 并通过 NapCat 自带的登录链接预填；仅允许回环 HTTP(S) 地址。不要分享带 Token 的地址，浏览器历史可能保留该链接。未配置该字段时仍打开普通页面；此功能不更改 QQ 登录状态。

### 引用、转发记录与小程序卡片

OneBot 11 保留合并转发 ID 和 JSON/XML 卡片中的标题、文本与 HTTP(S) 链接；这类通知不会仅因带卡片就触发主动回复。`read_chat_message` 可读取当前聊天收到或引用的消息，展开转发记录（默认每页 20 条），并返回下一页位置及截断提示。恢复历史引用时校验真实聊天 ID；转发里的作者只作为被转述的标签，不能授予成员或审批权限。转发附件可通过返回的 `mediaMessageId` 交给 `read_chat_media`，读取图像仍需视觉能力，音频仍需转写。

卡片文字并非链接内容或真实性证明。仅有小程序内部标识、过期/撤回消息、平台未提供可访问链接时，工具不能凭空恢复内容。链接通过已有网页工具按需访问；不会自动执行卡片指令或打开内部协议。嵌套内联节点有深度和输出预算；嵌套远程转发不会自动无限递归下载。

普通聊天可用 `inspect_knowledge_status` 查询当前获准知识范围的文档、分块、向量覆盖统计，不返回私人记忆或全局配置。

OneBot 合并转发图片若带有当前消息范围内的 CDN 地址，先走有上限的公共 HTTPS 下载，再按需查询桥接缓存；图片不必预先存在于机器人的 `get_image` 缓存中。直接下载失败可使用桥接提供的内容或地址，仍拒绝本机路径和私网目标。真实群转发验证读到两个节点，其中一个 JPEG 返回 `pixels-attached`，证明实际图片像素到达读图工具，不代表识别结论准确或图片内容属实。小程序 b23.tv 链接已解析，未自动抓取页面。验证使用临时存储，未发送群回复。

远程回复支持通过 `prepare_chat_reply.messages` 指定 1–8 条有序独立文字消息，或设置 `mediaOnly: true`。指定消息会替代最终文字；仅媒体模式只发送生成或引用的媒体，不强制附文字、喇叭表情或自动 @。没有可发送媒体或生成失败时简短报错，尚未完成的生成任务可在本轮结束后继续交付。自动媒体与显式引用使用相同投递 ID 防重复发送；原有收件范围、权限与不确定投递规则保留。轻松聊天可选用合适且已看过的本群表情包，不要求每条使用；只发语音的要求优先于表情互动。

接入平台的群聊和私聊按消息意图调整语气：闲聊和玩笑可以简短自然，无需惯例式免责声明；认真提问和执行任务仍按需要核实。不固定人设。这段指引仅在远程聊天轮次派发时加入，不修改全局系统提示词或已保存的会话设置，本地普通对话与项目对话保持原有行为。权限、审批、发送人身份、隐私和主动参与规则不变。自然程度仍受所选模型影响；自动测试验证作用范围和边界，不代表已验证真人聊天效果。

远程交流指引综合当前诉求、上下文、错误后果和用户表达偏好，区分社交回应、内容解读与求证／执行任务的需要；它们是可混合的维度，不是关键词触发的固定模式或人设。不要求闲聊都讲段子，也不机械附加免责声明、逐项看图描述、正式评分或任务邀约；涉及事实和行动时保留必要核实，声称看过图片前仍需实际读取。群中某个人的偏好不自动代表全群。没有额外分类器或模型调用，不修改本地会话策略。

氛围适应仅使用当前远程会话已提供的近期上下文，参考交流节奏、回复长短、正式程度、用词与幽默方式。群聊参考多人共同趋势，不因单个人刷屏或偶然起哄定型；当前明确要求和话题变化优先。不模仿辱骂、不冒充成员、不推断稳定人格或敏感特征。这是上下文适应，不是训练模型或建立长期人格档案；不额外读取其他聊天、不新增记忆、不跨会话传播风格，也不改变发言触发条件。

短时气氛与持续偏好分开处理：几条相关的接梗或起哄即可支持当下自然回应，不必等待多数人形成固定习惯，也不把短时气氛固化成人设。可参考当前会话的表情包／表情使用频率、时机、语义及是否单独发送，适量使用已查看且可发送的同会话素材或平台表情；不盲目复读、不编造未见素材，不改变触发与冷却规则。

同一连接、同一发送人尚在排队的连续文字可合并为一次模型回应，最多 8 条、跨度 8 秒、合计 6000 字符；附件、其他发送人和命令形成边界。不会中断已经执行的轮次，因此这是排队补充合并，不保证已开始处理的消息与后来消息合并。独立气泡应使用 prepare_chat_reply.messages，不按换行机械拆分；投递判断应依据回执，不能根据模型回复轮数猜测。

远程文字合并新增短等待：末条后安静 2 秒、从首条起最多等待 5 秒（另有通常最多 1 秒的调度间隔）。停止／状态／审批命令不等。本地输入框消息不受影响。

控制人批准的 `schedule_followup` 可回投原群／原私聊。重复任务至少间隔 15 分钟，要求次数或结束时间上限；`meaningful` 可抑制模型报告无变化的成功轮次。任务中明确目的、时间与免打扰时段，绑定变化或入口停用后阻止启动并复核权限。不会自动开启无限期闲聊，也不赋予普通群成员调度权限。已有群主动参与仍遵守开关及冷却。电脑和服务需要运行，不保证唤醒休眠设备或电话叫醒。

已登录的接入聊天页面提供**网页语音**：点击录音、结束一句后自动转写和回答朗读，或选择**让模型先说**。使用已配置转写与流式朗读服务，记录在当前会话，不带入输入框草稿、不产生平台投递。挂断释放麦克风和音频，并仅请求取消本面板待处理任务；打开原会话审批时保留任务。需 HTTPS 或 localhost 及麦克风许可。当前是交替对话，可选 Whisper 累计音频增量预览与停顿结束（见 [本地语音](LOCAL-VOICE.zh-CN.md)），只提交最终转写；不是全双工或原生流式模型；关闭／后台网页不能保证响铃或自动接听。

这些适配器尚未实现 QQ／微信原生通话。[NapCat 官方通话 API 请求](https://github.com/NapNeko/NapCatQQ/issues/1878)已关闭为不计划，维护者说明实现不对外开放。[社区 QQ AV 桥](https://github.com/ClaudiaGardner/maibot-qq-voice-call)依赖 Linux QQ／AVSDK、PulseAudio 和加载器 Hook，不是即插即用的 Windows OneBot API；本机未安装或验证。不能据此宣称已能接打原生电话或可靠地来电叫醒。

远程回复按语意选择消息气泡：完整的一层意思可以保持一条；自然的接话与独立补充可主动使用 `prepare_chat_reply.messages`，不必等用户明确要求拆分。不会按换行、字数自动切割，也没有每轮多条的配额。解释、列表、代码和任务结果按可读性保持完整。规划的气泡替代平台最终文本，不会再追加一份重复答复；工具回执明确计划条数与文字来源，不把准备完成当作投递成功。本地最终消息、纯对话和项目提示词不变。测试覆盖显式顺序、不重复投递、段落完整与本地历史不变；具体表达仍取决于配置模型和上下文，不能保证每轮都采用多条。

审批投递无法确认时不自动重发。审批过期或在本地答复后，未确认摘要转为 `uncertain-closed`，尚未发送的命令取消，后续消息（包括超时及重新获取提示）可继续发送；这不会批准操作，也不代表发送或撤回成功。每个连接最新的 `chat-delivery-failure` 记录保存超时、断连、拒收等有限分类，不保存平台错误正文；旧事件没有该记录时不能事后推断底层原因。

发送可用性与 WebSocket／登录状态分开判断。明确的 QQ 内核网络拒收（OneBot failed，内核码 1006514）记录为已拒收，最多按 2/4/8/16/30 秒重试五次；次数及下次时间持久化，每次检查路由和审批有效期。未知桥接错误、断连和超时仍保留为结果不明，不自动重发。耗尽重试后可在本地失败／未确认投递入口处理；忽略消息表示取消，不表示收到。本地诊断只记录数字协议码，不保存平台错误正文。WebSocket 或 get_status 正常不能证明 QQ 发送正常；失效 QQ 会话可能需要恢复登录。

远程审批分别检查结构化凭据字段与嵌套文本值；布尔权限元数据的字段名不再被误判为凭据。真实凭据、过长请求、恢复检查或未开启远程审批仍转本机处理；修复不会重放已经处理完的请求。

## 会话设定、语气与日记

每个接入卡片中的“聊天设定、语气与日记”可折叠展开。设定、日记和修订按连接、账号、目标聊天及本地会话绑定，不会进入其他群、私聊或本地普通/项目对话。

- 三组六维图提供 18 项表达倾向，支持沿轴拖动和键盘滑条。快捷预设只是调整起点，可继续微调；MBTI 是可选创作参考，不是真实人格判断。保存后在下一轮接入请求生效。
- “额外提醒”调低减少不必要的免责声明；“立场鲜明”增强主观意见的表达，不表示编造事实或隐瞒重要不确定性。“主动接话”不改变主动消息的许可、冷却或频率。
- 人可编辑文字设定和精简日记，并查看最近修订、将修订前内容载入编辑器后保存恢复。并发编辑检查版本，避免覆盖未看到的修改。
- 开启自动管理后，Bot 可按需使用 `inspect_chat_notebook` / `update_chat_notebook` 整理有本会话成员消息来源的风格和日记；不是每轮强制写日记，也不是另一次后台模型调用。Bot 不会改动人工语气轴、MBTI 或自动管理开关。日记是观察与回顾，不是身份验证、审批授权或完整历史。

## 长上下文恢复与嵌套转发

接入说明、当前群聊窗口和设定使用可替换快照，不再附在每条用户请求里永久重复保护。真正的用户消息与发送者归属仍保留。旧版已满的会话也可继续：历史请求过大时保留可校验的同会话原文归档、生成交接摘要，当前请求仍保留；模型可用 `read_spill` 分页回读。归档已经摘要过的部分不会每次再次送去摘要。摘要不可用会明确标记并保留原文入口，不冒充完整理解。当前单条输入本身超过容量时仍可能需要分块或更大上下文。

控制人 `/continue` 可继续最近的中断或上下文容量失败任务，仍检查入口、最新运行和未确认副作用，不重复执行工具或恢复暂停的定时计划。也可在原会话发新消息触发正常压缩；不需要删除历史或换会话。

`read_chat_message` 返回内层转发的同聊天 `messageId` 句柄，可继续逐层读取与分页；优先使用 NapCat 外层响应已经包含的内嵌正文，避免再次请求不可解析的内部资源 ID。缺少内嵌正文才请求远端，循环引用会停止，遍历仍有资源限制。转发中的姓名只作引述，图片仍需 `read_chat_media` 读取实际附件。平台没有返回或已失效的正文仍不能凭空恢复。

2026-10-26 验证：真实失败检查点在隔离副本中从约 1,293,953 估算 tokens 降到 24,589，原请求逐条校验一致；使用测试摘要，不代表真实摘要质量或线上恢复已验收。真实群转发外层包含四个内嵌记录（100/100/98/11 条），分页可读；重新请求其内部 ID 则返回 1200。合成回归另覆盖六层远端转发、循环和跨群拒绝。

### 可组合属性参考
聊天设置提供附件中的 30 种 OC 参考、高冷及语言、习惯、虚构身份、外观和关系等补充类别。分类参考 [萌娘百科萌属性目录](https://zh.moegirl.org.cn/萌属性)，并非完整百科镜像；条目说明为精简创作描述。可搜索、多选、调整强度，或添加任意自定义描述。三个六维图仅调表达倾向，外观与身份不会自动换算为人格分数。

一句话风格意图、所选参考、维度和可选 MBTI 可保存为本接入会话的命名组合；不会打包日记、历史或权限。选择后仍可手动微调，点击保存后下轮生效。数值是可编辑的创作起点，不是人格测量。仅当前选择进入模型上下文，未选择的库和保存组合不进入模型工具结果。Bot 可整理已有风格和日记，但不能覆盖这些人工设置。
