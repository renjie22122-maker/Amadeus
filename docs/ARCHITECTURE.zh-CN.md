# 架构

[English](ARCHITECTURE.md) | [简体中文](ARCHITECTURE.zh-CN.md) · [文档目录](README.zh-CN.md)

当前说明核对日期：2026-10-12。

## 模块边界

- `shared/`：领域与传输类型；`server/storage/`：SQLite、顺序事件、副作用和用量台账。
- `server/core/`：模型循环、调度入口、生命周期、上下文、委派、团队协调和确定性认知策略。
- `server/providers/`：协议序列化、流式响应、模型发现和实测用量。
- `server/tools/`：工具定义、发现、可用性、权限与审计调用。
- `server/services/`：执行、审批、文件、知识库、记忆、媒体、MCP 与后台工作。
- `server/http/`：鉴权后的本机 API/SSE；`src/`：React 界面。

RunEnvironment 通过明确依赖构造范围内的模型事实，不调度任务；RunPump 管理准入与停机收尾，最终收尾与团队协调有独立模块。Runtime 仍是服务组装入口和模型循环协调者，不能宣称已经消除了全部耦合。

## 生命周期与持久副作用

运行状态为 queued、running、waiting_user、waiting_approval、waiting_children、completed、failed、interrupted。终态不会复活；继续操作会创建新运行。结构化终止原因区分可恢复的限制／协议中断与真实失败。

工具执行意图和结果写入台账。确定未启动记为 not_started；外部结果不明继续标为 unknown。启动对账原子地中断旧运行、取消孤立交互。开启团队自动恢复后可检查现状再启动新轮次，但不能因为服务重启就重放任意命令。见[恢复说明](INTERACTION.zh-CN.md)。

SSE 使用持久事件 ID，最多补发 1,000 条；更大缺口刷新权威快照。文本增量是临时的，最终内容持久保存。模型流同时有总时限与字节空闲时限。模型循环对临时失败或断流最多重试五次，退避等待可取消；只在工具尚未执行时重新请求模型，已完成工具结果保留在检查点中，不重放工具。参数格式修正按成功模型步骤分别限次。

## 上下文与控制

主请求实测 token 校准本地估算；工具定义和图片也计入容量。压缩保留最新要求、完整近期工具调用／结果对和按时间排列的逐字请求来源账本。摘要失败可将旧历史转存范围内 spill；受保护要求仍放不下时明确报错。

重复读取仍实际执行，之后才可用引用或差异减少传输。来源哈希、保留基线和模型／工具配置用于防止陈旧复用。不会用缓存回答或旧测试成功替代执行。见[前缀缓存](DEEPSEEK-CACHE.zh-CN.md)。

认知控制器从真实观察提取重复、进展和验证信号，排除事件等待，生成有界建议与恢复方案。它是确定性策略，不是第二个 LLM Agent。后续评估记录变化，不等于证明干预带来因果收益。

## 团队

规划编译先核对契约和依赖图，再调度。只读黑板统一投影任务、成员可见消息、产物、证据与未知副作用；选择性上下文有数量边界并标明遗漏。原始记录仍是权威来源。

持久成员可以通过新运行继续，保留会话历史；隔离、祖先关系、深度、权限、角色版本和未解决副作用继续约束续跑。可写子副本需版本化审查与合并。角色交接只转移协调权，不授予执行权。

每会话模型并发默认 3，每棵任务树累计子执行默认 8；显式设 0 取消该数量限制，继续成员也计入。深度、预算、服务商配额和团队扩缩容限制仍独立。见[调度](PLANNING-AND-ROUTING.zh-CN.md)。

## 边界

这是单宿主运行时，不是分布式共识或外部操作恰好执行一次的系统。证据来源不等于语义正确，文件观察不等于抗恶意并发锁。广泛性能与安全结论需要独立评测。

记忆、策略和图谱路由已迁入 server/http/memory.ts，显式依赖 Store、Configuration、MemoryIndex。HTTP 组合根保留统一鉴权与生命周期钩子；本次未宣称 App.tsx 或工具注册表已全面拆分。

## 基于证据的反思

任务快照附带有界、确定性的核对摘要：已声明目标完成情况、来源有效的工具证据、已记录检查、独立检查、过期检查、阻塞项与未知副作用。证据必须属于同一任务树，已调度命令不算通过证据。后续检查建议面向验收条件中的反例；不编造正确率，未声明的遗漏要求仍未知。这扩展现有建议型控制层，不等于新增自主批评模型，不为每个任务强制启用反方团队，也不证明调度已达到全局最优。现有全文／引用／差量上下文复用保持不变。

### 安全审查与证据绑定的质疑

涉及软件信任边界时，助手可发现并使用 `prepare_security_review`。该工具为身份、
授权、不可信输入、共享状态转换、外部事件、秘密信息及文件/网络访问生成**尚未测试**
的反例设计。助手选择适用边界并纳入验证任务；拒绝测试应有合法请求作为正对照，
同时检查持久化状态。执行审批只允许运行操作，不代表交付的软件已通过安全审查。

具体疑点可通过 `record_task_challenge` 保存；未解决疑点阻止受影响任务最终完成。
`resolve_task_challenge` 必须引用质疑提出后生成的当前任务验证事件，且执行回执
成功、产物版本一致。旧的全绿结果不能关闭新质疑；任务契约变化或产物验证过期后，
已解决疑点重新打开。作者自检与独立检查分别记录，生成审查清单或记录质疑本身不能
作为完成证据。交付循环最多给予两次纠正机会，不无限复审，不重放未知副作用。

上述机制证明检查记录及版本来源，不证明检查在逻辑上充分反驳疑点。适用边界选择、
漏洞发现仍依赖模型和可用证据。静态检查必须如实标注，不能冒充已执行的攻击测试。
没有经过校准的安全分数，也不要求普通聊天强制启动审查者，更不保证无漏洞。
反思分别记录事实、计划、工具、证据、记忆和答案的不确定状态，不编造概率。
无需新增依赖或修改首次启动/快捷启动。

宿主也会根据已声明任务中的风险词和代码产物自动在任务快照中加入检查设计，无需用户另问或模型先调用工具。这是启发式触发，不覆盖没有计划、未声明变更或所有风险；清单执行仍依赖模型，已记录的未解决质疑则由宿主拦截交付。

### 统一交付证据与收敛信号

宿主把任务状态、未解决质疑、适用的经验检查和结果不明操作投影为同一份只读交付报告，
复用现有权威记录，不再增加可写台账。`inspect_delivery_evidence` 返回前刷新产物验证；
最终完成检查刷新后使用相同阻塞列表，并记录 `delivery.assessed` 事件。

红色表示现有必需检查未解决；黄色表示没有此类阻塞但仍有覆盖缺口；绿色只表示已记录的
必需检查满足，绝不代表代码正确或没有漏洞。没有证据为未评估，受阻不算通过。
报告把声明产物、验收条件与直接依赖它的验证任务关联；全部关联验证完成并有记录后，
才报告后继检查覆盖。产物检查与这类声明关系分开，未声明依赖和测试是否充分仍是未知。
详细报告最多展示 100 条记录、50 行影响关联，并标明省略数；阻塞判断不截断。
这是工具与上下文报告，没有新增 UI 红绿灯，也不是自动风险分类器。

确定性控制器分别跟踪完全重复轨迹，以及输出变化但操作目标不变的轨迹。连续八批同目标
且无任务或验证进展时，可以提示复查计划，每十二批最多一次。此信号本身不终止任务：
时间戳变化可能掩盖轮询，但正常观察也可能持续变化。不同目标的探索和事件式等待不按
此类循环处理，任务或验证进展会重置窗口。目标新颖度只是不同请求占比，不是语义新颖度
或校准置信度。原有完全不变循环的限制保留。

无需新增依赖、数据库迁移或修改首次启动。后端变更需重启服务才能生效；再次打开启动器
不会热更新已经运行的服务。

### 接通进展反馈闭环

工具批次结束后，先通过现有验证服务刷新已记录检查的声明产物及依赖指纹，再进行认知观察。
这里只刷新验证有效性，不执行测试。产物改变可在最终交付之前触发覆盖退步反馈。

进展同时记录增加与减少：已完成任务重新打开或被移除、已记录检查失效时，优先报告退步，
不会被同时新增的完成项掩盖。该变化要求核实当前验证，不自动重放操作。范围修订也可能
解释变化，因此信号本身不代表软件缺陷。有效检查被新的有效检查替代不算损失，
最终完成仍由既有门槛决定。

同一运行的上下文现在包含最近策略效果及待处理的有界恢复建议，没有任务板时也能得到
反馈。已处理或超过四批的恢复建议不再注入；重置和其他运行不会继承该反馈。
轨迹变化仍与验证成功分开，覆盖退步单列到学习效果汇总。这些观察不会自动增加可信度、
激活经验、调用新的批评模型或授予权限。经验仍沿用有证据的候选形成与下次任务检查链路。
无需新增依赖或更新启动项；加载本轮后端变更需要重启。

### 受控恢复检查

恢复建议现在带唯一 ID。Agent 可通过正常工具注册表与权限检查发现
`inspect_recovery_step`，选择当前建议的一步。执行器只接受三类诊断：
检查已有操作记录、刷新声明产物验证、读取交付报告。不运行命令、任意路径访问、
安装、回滚、测试或权限修改。其他建议仍通过正常受控工具或用户范围决定处理。

每个运行、建议、步骤只领取一次并记录收据。重复调用返回原收据，包括未完成或失败
的检查，不再次执行。新执行要求建议仍待处理且不超过四批；重置移除建议，
被替换或其他运行的 ID 会被拒绝。检查期间崩溃可能留下检查中收据，它是诊断状态，
不代表操作结果已经解决，也不新增完成阻塞。

收据回到本运行认知上下文。检查完成不等于恢复成功，不解除结果不明操作，
也不能充当任务完成证据。原有效果评估仍区分验证进展和策略变化。
这属于有界诊断执行，不是任意自主恢复或学习式策略优化器。无需新增依赖、
迁移或修改启动项。

### 可改变工作区的恢复契约

`prepare_recovery_action` 记录原因、预期结果、声明的已有路径、产物及依赖指纹、
工作区身份、计划版本、一个动作和一个检查。`execute_recovery_action` 通过原有
工具执行器执行两者，保留逐工具权限、审批、沙箱、Hooks 与效果记录。
动作支持写文件、编辑与命令；检查支持包含明确预期片段的文件读取，或命令
（可附预期输出片段）。命令零退出码只是观察结果，不是语义正确性证明。

契约十分钟过期，每轮最多准备三个。命令沿用普通执行的 1–1800 秒时限（默认 120 秒），默认 10 秒后让同一进程转后台。
范围、计划、前置文件变化或存在未知操作结果时拒绝执行。分派前只领取一次，
重复调用返回收据，包括中断后仍执行中或未知的收据，不自动重试或回滚。
同一运行的恢复动作不能并发执行。审批等待与命令运行时限仍分开。

结果区分有效进展（声明条件被观察到）、无效、退步（原有有效检查变为失效）和未知。
子工具事件 ID 关联动作及检查，收据回到认知上下文。准备与包装工具不能冒充完成证据，
结果不会解除未知操作或激活记忆。既有最终验证、质疑与经验检查继续生效。
当前策略不自动优化恢复方案，也不在失败后自动执行新提案；后续受控工作仍由模型选择。

声明的前置路径必须已存在。快照只在分派前核对，不是操作系统锁，审批或执行期间的外部
修改及未声明依赖仍有限制。命令检查需真正针对预期条件设计，宿主不能证明测试充分性。
无需新增依赖或修改启动项。

后台恢复持久化 waiting-action / waiting-check 和原任务 ID。通过事件式
wait_background_command 等待后，以相同契约 ID 再调用 execute_recovery_action；
只允许启动尚未执行的后续检查，不重新启动原动作。验证命令也可以转后台，
等待时重复查看收据不会阻塞。执行时限与审批沿用普通命令语义；启动后不因最初契约
到期而取消任务。未知结果停止后续链路并阻止交付，待处理恢复也不能提前完成。
后台完成通知进入模型，模型接续契约；这不是模型离线时独立执行验证的调度器。
启动脚本无需修改，继续使用已有源代码指纹重建机制。

### 由结果影响恢复选择

恢复结果生成运行内策略反馈，依据匹配的真实工具事件或后台终态结果。
拒绝授权、缺失收据和未知结果不成为已学到的失败证据；有效进展仍只是可参考选项，
不会授予权限或变成校准成功率。

已有证据表明无效或退步时，同一声明产物及范围条件下的相同动作不再允许准备，并记录
拒绝原因。参数对象顺序、命令理由措辞变化不算新策略，放宽验证条件也不能绕过。
动作或声明前置条件改变后，可以在已有尝试上限内重新考虑。限制作用于恢复契约入口，
不是全局拦截所有普通工具。反馈进入当前运行上下文，不跨对话或项目，不自动激活记忆，
也不自动选择其他命令。

这是基于结果的防重复策略，不是因果或反事实推断。反事实明确标为未观察，
声明条件之外的环境变化、检查不充分及混杂因素仍有限制；没有收益估计、
自动回滚或全局学习策略。无需新增依赖或启动项变更，后端更新需要重启。

## 能力准入与独立复核交付契约

注册工具在发现与调用时共用能力准入函数。策略、钩子和审批等待后，调用前重新核对持久化权限、工作区与隔离身份、执行设置及拒绝规则。各适配器仍负责审批、隔离和效果记录；Provider HTTP 请求尚未统一进入这个工具内核。这不是 OS 隔离的替代品，也不是原子文件锁。

实现任务可声明 `requireIndependent: true`，交付与团队收尾必须具有当前有效、由现有验证器认定为独立的检查证据，作者自检不能单独满足要求。该字段参与契约修订；反例质疑仍需当前证据解决。独立性描述记录中的作者关系，不保证语义正确、不同模型共识，也不会自动启动审阅者。

有界团队共享摘要增加验收条件（最多 800 字符并提示截断）、提供与依赖接口、未满足的任务依赖及独立复核状态。原始契约仍是权威记录，让主持者无需逐份阅读队友完整计划。接口声明不代表兼容性已经证明。本次无新增依赖、迁移或启动脚本要求。

声明交付文件的任务即使不属于团队，也必须有当前有效的检查记录才能完成交付。未声明文件的任务仍可能以黄色提示未验证覆盖；黄色不代表语义验证通过。

## 恢复与存储边界（2026-10-12）

resume-preparation 负责中断检查点修复且不重放；recovery-tools 和 HTTP effects 模块分别负责对应入口。副作用恢复协议核对宿主绑定的持久回执，与文件完整内容核对分开。媒体提交前以事务保存意图及引用；后台命令的终态与副作用结算一起提交。Runtime 仍是服务组合与模型循环协调者，拆分是渐进改进，并未全部完成。

Store.maybe 仅在 NOT_FOUND 时返回 undefined。记录 JSON 损坏抛出 RECORD_CORRUPT，不输出记录正文；数据库故障直接传播，不再伪装成缺失。核实过程中的存储故障也不会被静默当成文件未知。

服务组合进一步拆为 core/runtime-services 与 http/maintenance-services；MCP 发现、浏览器和桌面调用整组注册位于 tools/mcp-tools，文件传输复用 FileScope 句柄方法。内置工具仍由宿主注册；Agent 只能发现已启用 MCP 服务的工具，Skill 和自产脚本不自动成为拥有更高权限的可信工具。

## 对话读取与发送响应

对话 HTTP 投影已拆到 server/http/conversation-view.ts。会话记录先在 SQLite 按范围筛选，再解码 JSON；活跃状态检查只读运行元数据，新一轮只加载最近一轮检查点，不再加载全部历史轮次。任务板和成员列表在单次请求内复用。

服务器确认收到消息后，界面结束发送状态，后续刷新独立进行。缓存对话使用最近 HTTP 快照游标增量读取，不能用可能有缺口的 SSE 最新事件充当游标；旧消息的送达状态仍同步更新。并发全局刷新合并请求，聊天、设置和后台页的轻量刷新不再携带记忆和文档目录，进入资料页再加载完整数据。后台轮询等请求完成再安排下一次；离开模型连接时取消旧发现请求。

限制：首次打开未缓存对话仍传输完整历史，五项缓存不等于持久分页。单轮超长输出及同步数据库后台工作仍可能影响响应。本次不代表消除了恶意父目录替换竞态，也不代表不可用的 Docker 或严格 AppContainer 已通过隔离验证。

消息提交回执只含运行元数据，不回传模型检查点。
