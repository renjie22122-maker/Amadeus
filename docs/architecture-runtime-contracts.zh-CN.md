# 运行行为与诊断

[English](architecture-runtime-contracts.md)

- **知识库 → 测试检索 → 本次检索详情**：显示本次请求的诊断编号、配置与实际执行路径、降级原因及本地向量读取行数。零命中也有自己的编号。缓存覆盖是可检索的范围，不等于本次读盘量，也不代表外部索引计算了多少次相似度。零命中不能证明资料不存在。
- 大库的内建路径是分批精确检索；外部索引可复用有效缓存。无关项目写入不改变当前范围的代际。升级后首次检索可能建立新清单，不重新生成文档向量。缓存被淘汰、授权范围内的向量或有效文档集合变化，仍可能需要读入向量。
- 每个模型步骤按运行读取待办反馈，按会话顺序交付新消息，保留已交付历史。暂停后仍有在途运行的定时任务会继续核对结果。同一批待交付附件共享 15,000 字符正文预览，保留所有附件 ID 与各自续读位置；图片另按视觉预算处理。
- 网页根据当前视图的版本决定是否刷新，未变化的条件请求也不重新组装页面数据。连接恢复时仍同步当前会话。暂停读取的客户端不会无限积压；过大的回放直接恢复快照，不承诺还原每一个临时 token。
- **设置 → 当前运行的服务**：显示构建版本、可验证的提交、是否包含本地改动和构建时间。旧版或开发环境未记录提交时显示未知。健康检查验证服务生命周期、SQLite 可读取；不会为了检查启动推理。日记整理循环的连续异常与单个会话的提取失败分开记录，统计自进程启动算起。
- `pnpm test:contracts` 运行固定的合成回归集，覆盖检索、记忆、调度、办公文档与运行恢复；它不评估付费模型端到端任务成功率。`pnpm verify:server` 在独立目录编译、启动临时服务并冒烟验证，不覆盖线上构建。

浏览器回归：先构建前端，设置 `AMADEUS_TEST_REFRESH=1`；如果前端不在默认的 `dist` 目录，另设 `AMADEUS_TEST_UI_DIST` 指向该目录。运行 `node --import tsx --test tests/workspace-refresh-browser.test.ts`。测试使用临时数据库和独立浏览器，验证未变化的心跳不会拉取状态，以及变更后网页会刷新。

## 架构审查：已验证的变化与剩余缺口

| 建议                   | 当前行为和验证边界                                                                                                                                                                                                                                                                                            |
| ---------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 把诊断绑定到实际运行   | 网页对话和桌面 Dot 可按需展开运行回执。显示本次运行最近 20 次已记账请求的首段正文、首个推理信号和总耗时，最近 20 次已结束工具的耗时、最近一次记忆召回，以及已关联的外发状态与最长入队到平台回执用时。不开面板不请求回执。旧记录不能补算，平台消息编号不等于已读。计时从模型调用包装层开始，不等于网络首字节。 |
| 子任务结果可追溯       | 复用同一个子代理时按指定运行和会话取最终答复；中断的部分输出不会成为交付。按根任务的实际后代统计并发和等待，保留原有审批及预算。                                                                                                                                                                              |
| 先限制可见范围，再检索 | 召回与指定范围的向量补齐先按 SQLite 范围索引取候选，之后仍逐项检查来源、状态与会话可见性。等待 embedding 时若原会话切换资料域，则此次不返回旧范围的记忆。既有衰减、修订和撤销规则不变。                                                                                                                       |
| 保留本地优先与桥接边界 | 点开回执不会触发推理或投递；它不包含聊天正文、提示词或工具参数。Dot 只能查自己绑定的会话。未获得回执、平台已接受、用户已读是不同的状态。                                                                                                                                                                      |

尚未验证：真实长任务的端到端成功率、不同模型在同一代表性任务集上的成本与质量、数小时空闲后到可操作的耗时分布。单次模型计时不能分离上游排队和推理开销，合成回归不能替代这些评估。Windows 隔离的生产可用性仍以对应后端实测清单为准。

复测待办读写：`node --import tsx scripts/inbox-profile.mjs` 仅创建内存库，对旧扫描与新索引分别预热并采集 32 个样本。Windows、Node 24.20.0、30,000 条无关历史的一次对照中，单次读取 p50 为 24.881 → 0.009 ms，p95 为 27.493 → 0.010 ms；每批 32 条入队并标记已交付的 p50 为 0.408 → 0.511 ms。索引有写入代价；这是局部 SQLite 实验，不代表线上整轮聊天耗时。
