# Bot 启动与独立状态提示

[English](BOT-STARTUP.md) | [简体中文](BOT-STARTUP.zh-CN.md)

[scripts/bot](../scripts/bot) 将聊天桥接和轻量提示进程独立于 Amadeus 服务。Windows 入口使用当前用户的交互式、按需计划任务，不添加开机或登录触发器，不保存 Windows 密码，不停止服务，也不操作 benchmark。新启动的任务进程不依赖 Codex 或终端；注销、关机、睡眠仍会终止或暂停可用性。复用的旧进程仍保留原有生命周期，安装计划任务不能把已经运行的服务重新挂到任务下。

## 本地配置

1. 将 `scripts/bot/config.example.json` 复制到 Git 忽略的 `.data/bot/config.json` 或其他私有目录，替换所有 `YOUR` 占位项，使用绝对路径。需要 Node 24。此文件允许启动配置的程序，应作为可信本机配置保护。
2. 填写桥接程序、参数字符串、工作目录和环境变量。示例为 Windows NapCat，路径不写死在程序中。NapCat 保留示例中的五项 `NAPCAT_*` 环境变量，最后一个参数填写机器人账号。通过程序路径和参数匹配防止等待登录时重复启动。端口可连接只是就绪线索，不代表已验证账号或登录成功。
3. `offline` 配置实际数据库、机器人账号、与接入设置一致的回环 WebSocket 地址和健康接口。令牌从 `tokenEnv` 环境变量，或 `tokenFile` 加 `tokenPath` JSON 属性/数组下标路径读取。计划任务必须能访问指定环境变量。示例选择第一个 WebSocket 配置，应改为实际启用的配置项。不要把令牌放入 Git 或快捷方式参数。
4. 状态、去重账本、锁文件及日志路径放在本机私有可写目录；选用不冲突的 `taskPrefix`。可用 `notice` 和 `reauthorizeNotice` 配置简短纯文本通知。
5. 执行 `powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts/bot/Install-Bot.ps1 -Config C:\absolute\private\config.json`。生成 **Amadeus + Bot** 与 **Bot only** 桌面快捷方式；`-NoShortcuts` 只注册任务。安装拒绝覆盖运行中的任务，不启动服务。启用新版提示进程前应停止旧的独立兜底进程，否则两套实现可能重复回复。
6. 双击入口。仅 Bot 入口打开桥接登录页；登录失效时仍须扫码，不能绕过平台验证。组合入口只在健康检查不通过时启动 Amadeus，不停止或重启健康服务，也不自动恢复人为停止的服务。

提示进程也可单独执行：`node scripts/bot/offline-notice.mjs /absolute/private/config.json`；其他系统自行配置服务管理器。目前消息兜底适配 **仅支持 OneBot 11**，不能当作 Telegram、WhatsApp、微信的通用协议实现。

## 何时提示

- 只读数据库，实时核对已授权的账号、连接地址、会话和发送者。私聊必须来自绑定用户；群聊仅响应真正的 @机器人 或配置的命令前缀，不接普通闲聊，不响应机器人自己。
- 默认每五秒检查一次、每次超时两秒；连续三次失败后启用离线提示，发送前再次检查。服务健康但模型较慢/忙碌不视为离线，也不保证识别所有模型卡住或单条线路故障。
- 被明确标为 `reauthorize` 的已停用私聊，可向原绑定用户提示本机重新核对授权，服务在线时也有效。群聊待授权和手动停用均保持静默。提示不授予权限，也不代表任务已受理。
- 默认每个会话两分钟最多一次、全局十秒最多一次。过滤旧消息、重复消息、跨群及未授权请求；去重/冷却记录有界且先落盘再发送。不自动重试不确定投递，账本写入失败不发送；配置、数据库、账本无效时停止处理。不调用模型，无推理费用。
- QQ 或桥接本身离线时无法发提示。状态文件区分桥接断开、Agent 可用性和发送失败，不记录消息正文或令牌。

Amadeus 设置页区分“手动停用”“待重新授权”“已连接”“连接断开”。权限、模型、资料范围变化不能沿用旧授权：核对后重新启用并保存。普通聊天仍需本机审批，“同意了”不是审批命令。手机远程审批须显式开启受控的远程工作入口，由绑定控制人使用完整操作对应的一次性命令；敏感、过长或恢复检查类操作仍在本机处理。

## 测试与维护

`pnpm test` 包含离线/恢复、撤销授权、并发、冷却、重启去重、发送不确定及重新授权回归测试。Windows CI 用模拟进程验证首次启动、已运行复用和含空格路径，不打开 QQ、不向真实群发送测试消息。聊天测试覆盖待授权原因保留和手动停用。不通过制造真实停机来验证。

卸载时只停用/删除配置前缀对应的计划任务，不批量终止 Node 或 QQ。配置与令牌来源不要提交或放入公开备份。拉取代码不会自动升级运行中的进程，须另选合适时间更新对应辅助进程或服务。

### 平台会话健康检测（可选）

在私有启动配置中设置 `bridgeHealth.enabled` 和 `bridgeHealth.autoReconnect`，可启用有限恢复。独立兜底监测每分钟探测登录账号、平台在线状态和新鲜好友列表，在本地状态文件的 `bridgeHealth` 字段记录结果。WebSocket 连通不等于 QQ 能正常收消息。

此前非空的好友列表连续三次变空，且已过启动三分钟宽限、两分钟未收到消息，才判为可疑。探测错误、普通静默、首次安装的空列表、账号不符和未登录不会触发重启。这是启发式判断，不是故障的绝对证明：正常删光好友也可能命中。自动恢复需要显式启用，至少间隔十分钟、每小时最多两次，基线与次数在监测重启后保留。遇到登录验证仍需用户扫码，不收集密码或验证码。

恢复同时匹配配置中的桥接程序路径和进程参数，拒绝多个候选根进程，停止前再次核验进程创建时间，只处理它的子进程树。其他 QQ 会话、Amadeus、RAG 和 benchmark 不属于重启目标；不会发送测试消息或重放漏收消息。不支持这些 OneBot 接口的桥接可保持此功能关闭。

机器人联合启动入口即使发现 Amadeus 主服务已在线，也会调用可重复执行的 Amadeus 启动器，补查已配置的本地语音和 RAG 服务。健康实例直接复用，不重启主服务。语音启动为轻量启动，模型等转写或合成请求到来后才加载。
